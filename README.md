# IACPaaS MCP

Самостоятельный MCP-сервер, собственный агентный цикл и веб-чат для работы с инфоресурсами IACPaaS. Основная предметная область — технологические газы, их онтология, состав и нормативные ограничения. MCP подключается к VS Code и другим клиентам независимо от веб-интерфейса; весь веб-комплект можно запустить в Docker.

## Возможности

- MCP через stdio и Streamable HTTP с общей доменной логикой.
- Типизированные аргументы, JSON Schema и структурированные результаты.
- Ограничения глубины, размера аргументов и ответа.
- Серверная политика доступа к изменяющим операциям и подтверждение записи в CLI.
- Общий разговорный цикл для веб-чата и CLI с реальной моделью: пояснение перед действием, чтение MCP, промежуточные события и итоговый Markdown со ссылками.
- Полная история в SQLite и отдельный сжимаемый рабочий контекст модели.
- Редактирование запросов и повторная генерация с сохранением исходной версии, архив, восстановление и удаление диалогов.
- Светлая, тёмная и системная темы; компоненты JetBrains Ring UI и шрифт Inter.
- Настройки модели/API-ключа и логина/пароля IACPaaS для пользователя браузера.
- Подключение OpenAI-совместимых моделей и конфигурация custom agent для VS Code.

Поддерживаются два источника: `MockBackend` с синтетическим графом и read-only адаптер реальных ресурсов IACPaaS. Источник выбирается через `IACPAAS_BACKEND`; ошибка платформы не включает mock автоматически. Режим модели `demo` выполняет заданные сценарии без LLM; `openai` использует настроенную модель.

Для реальной платформы укажите в приватном `.env` `IACPAAS_BACKEND=iacpaas`, логин, пароль и пути ресурсов в «Моём фонде». Программа получает JWT и читает universal-экспорты. Подключение и ограничения: [интеграция IACPaaS](docs/iacpaas-integration.md).

## Установка и быстрый запуск

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/). На Windows те же шаги выполняются в PowerShell; Docker и WSL для прямого запуска не нужны — см. [запуск в Windows](#запуск-без-контейнера-в-windows-powershell).

```sh
git clone https://github.com/Rewentes/iacpaas-mcp.git
cd iacpaas-mcp
uv sync --frozen
uv run --frozen iacpaas-agent "найди университет и покажи метаданные" --model demo --trace traces/demo.jsonl
```

При stdio-подключении агент запускает MCP-сервер автоматически. В PowerShell для воспроизводимой проверки без интерактивного подтверждения:

```powershell
uv run --frozen iacpaas-agent "найди университет и покажи метаданные" --model demo --trace traces/demo.jsonl --non-interactive
```

## Веб-чат

### Docker

Создайте приватный `.env` и настройте backend и пути ресурсов:

```sh
cp .env.example .env
```

Запуск:

```sh
docker compose --env-file /dev/null up -d --build
```

В PowerShell на Windows используйте `NUL` вместо `/dev/null`, а `.env` создайте через `Copy-Item .env.example .env`:

```powershell
docker compose --env-file NUL up -d --build
```

Откройте [веб-чат](http://127.0.0.1:8080). История и профили сохраняются в постоянном томе. В **Настройки → Вход в IACPaaS** введите логин и пароль; отдельная кнопка проверяет вход и чтение одного ресурса без обращения к модели. API-ключ и модель выбираются там же. Пути разрешённых ресурсов задаёт оператор в `.env`. Настройки браузера действуют на веб-чат; внешний MCP использует собственное окружение. Управление, резервное копирование и настройка LAN-доступа: [docker.md](docs/docker.md).

### Запуск без контейнера

Веб-приложение использует общий MCP-сервер, хранит переписку в SQLite и поддерживает OpenRouter, OpenAI API и отдельный профиль Codex. Провайдер и модель выбираются в настройках; платные запросы выполняются при отправке сообщения или явной проверке модели.

```sh
uv sync --frozen
cp .env.example .env
# Заполните OPENROUTER_API_KEY в локальном .env.
uv run --frozen --env-file .env iacpaas-web --host 127.0.0.1 --port 8080
```

Откройте `http://127.0.0.1:8080`. Модель задаётся через `OPENROUTER_MODEL`; значение по умолчанию — `deepseek/deepseek-v4.1-flash`. Без ключа приложение не подменяет LLM демонстрационными ответами: диалоги доступны, а отправка запроса сообщает об отсутствии настройки.

Если итоговый текст не разбирается из-за оформления или ссылок, агент один раз просит модель исправить формат по уже полученным данным, без новых вызовов MCP. Исправленный вариант проходит обычную сверку с источниками. Пустой ответ, отказ провайдера и исчерпанный лимит вывода показываются раздельно; незавершённый текст не публикуется. После ошибки исходное сообщение остаётся в истории и автоматически повторно не отправляется. Лимит вывода задаётся `AGENT_OUTPUT_RESERVE` (по умолчанию 4096); у рассуждающих моделей он может включать служебные токены.

При `IACPAAS_BACKEND=iacpaas` веб-агент работает с настроенными ресурсами платформы. Специальный инструмент `get_gas_specification` возвращает нормативные границы состава газа с единицами и знаками ≤/≥. Они не выдаются за фактически измеренные примеси. При `mock` интерфейс явно показывает тестовый источник. Инструкция и HTTP API: [web.md](docs/web.md).

Ответ ограничивается запрошенными сведениями; сравнения и практические выводы добавляются по просьбе. При числовом несоответствии агент использует общую единственную попытку исправления ответа по текущим документам MCP, без старой истории и дополнительных чтений. Исправленный текст повторно проходит числовую и смысловую сверку. Служебные предупреждения доступны под «Сведения об источниках».

Для OpenRouter запросы используют `temperature=0` и `seed=42`, если модель объявляет поддержку этих параметров; это применяется к основному циклу и проверке. Поддержка проверяется через каталог моделей и кэшируется на 15 минут. Эти настройки уменьшают вариативность, но не гарантируют дословную повторяемость разных контекстов, изменившихся данных или внешней инфраструктуры.

### Запуск без контейнера в Windows (PowerShell)

Прямой запуск не требует Docker, WSL или активации виртуального окружения: `uv` сам скачает Python 3.11+ при необходимости, а зависимости установит `uv sync`. Проверено на Windows 11 в PowerShell 5.1 и PowerShell 7.

Установите Git и `uv`:

```powershell
winget install --id Git.Git -e --source winget
winget install --id astral-sh.uv -e --source winget
```

После установки откройте новое окно PowerShell, чтобы обновился `PATH`. Затем клонируйте проект и запустите приложение:

```powershell
git clone https://github.com/Rewentes/iacpaas-mcp.git
Set-Location iacpaas-mcp
uv sync --frozen
if (!(Test-Path .env)) { Copy-Item .env.example .env }
# Демонстрационный режим: IACPAAS_BACKEND=mock уже задан в .env.example.
# Для реальных ответов модели добавьте OPENROUTER_API_KEY в .env.
uv run --frozen --env-file .env iacpaas-web --host 127.0.0.1 --port 8080
```

Откройте чат во втором окне PowerShell:

```powershell
Start-Process http://127.0.0.1:8080
```

Сервер останавливается сочетанием `Ctrl+C` в первом окне. Если `winget` недоступен, установите Git и `uv` вручную и проверьте, что `git` и `uv` есть в `PATH`.

Без ключа провайдера чат открывается, история и настройки работают, но отправка запроса сообщает об отсутствии настройки — демонстрационная подмена LLM не включается. `IACPAAS_BACKEND=mock` включает синтетические ресурсы MCP; для реальной платформы задайте `iacpaas` и учётные данные, как описано выше.

## Как проходит запрос

```text
Веб-чат → HTTP/SSE → ConversationAgent ← CLI с реальной моделью
                         │ модель ↔ вызовы инструментов
VS Code / другой MCP-клиент ──┤
                         ▼
                   MCP-сервер
                         ▼
                GraphService → IACPaaS / mock

SQLite: полная переписка, источники, события, отдельная рабочая сводка
```

Модель сначала определяет смысл вопроса. Для объяснения метода или приветствия чтение базы не требуется; для фактов она выбирает инструменты MCP. Интерфейс получает пояснения и события по мере работы. После чтения модель формулирует ответ, а отдельный проверочный проход получает его смысловые блоки и полные исходные результаты MCP. Цитаты поддерживают `[e1]`, списки и диапазоны `[e2–e5]`. Если подтверждена только часть фактического ответа, она публикуется с явной отметкой. Проверка остаётся автоматической, а её основания доступны в отчёте.

Поиск `query_graph` в режиме `auto` сопоставляет `id` и `metatype` точно; для остальных полей используется подстрока. `match_mode=contains` включает явный поиск по подстроке. Счётчик `total_matches` относится к условиям `query`, а `complete=false` отмечает неполную выдачу.

Рабочий контекст ограничен `AGENT_CONTEXT_LIMIT` с резервом `AGENT_OUTPUT_RESERVE`. При приближении к лимиту старые завершённые сообщения сжимаются моделью в сводку до `AGENT_SUMMARY_BYTES`; полная история для человека сохраняется. Старые результаты инструментов могут удаляться из рабочего запроса целыми обменами, при этом источники и журнал сохраняются. Оценка токенов консервативная, по размеру UTF-8, а не точный счётчик провайдера.

На пустом экране показываются два случайных примера из десяти заранее подготовленных вопросов. Нажатие на пример заполняет поле ввода. Вопрос отправляется после отдельного действия пользователя.

Клиенты используют один контракт инструментов. MCP-сервер проверяет аргументы и доступ, а GraphService выполняет операции над графом независимо от транспорта.

## Запуск сервера

```sh
# stdio
uv run --frozen iacpaas-mcp

# HTTP, после настройки MCP_HTTP_TOKEN в окружении
uv run --frozen iacpaas-mcp --transport http --host 127.0.0.1 --port 8000
```

Для подключения CLI к HTTP-серверу задайте тот же `MCP_HTTP_TOKEN`:

```sh
uv run --frozen iacpaas-agent "посчитай граф /demo/university" --model demo --transport http --url http://127.0.0.1:8000/mcp
```

HTTP без TLS поддерживается для loopback-подключений. Для доступа вне доверенного компьютера настройте HTTPS и защиту доступа на reverse proxy. Профили веб-чата различаются по защищённой cookie браузера; это не полноценная система пользовательских аккаунтов.

## Настройка модели

Скопируйте `.env.example` в `.env` и заполните `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`. Endpoint должен поддерживать Chat Completions и tool calling.

```sh
uv run --frozen --env-file .env iacpaas-agent "найди университет и покажи метаданные" --model openai
```

CLI `iacpaas-agent` и `iacpaas-mcp` не загружают `.env` автоматически: используйте `--env-file` или экспорт переменных. Веб-сервис дополнительно использует `python-dotenv`; явный `--env-file` остаётся предпочтительным способом запуска. Ключи и токены не должны попадать в git или трассы.

## VS Code

1. Откройте корень репозитория и выполните `uv sync --frozen`.
2. Запустите `iacpaas` через **MCP: List Servers**, используя `.vscode/mcp.json`.
3. Выберите custom agent **IACPaaS Explorer** из `.github/agents/iacpaas.agent.md`.

Конфигурация VS Code читает локальный `.env` через `envFile`. Для других оболочек передайте окружение либо команду `uv run --frozen --env-file .env iacpaas-mcp`. MCP запускается независимо от веб-приложения.

Для HTTP предусмотрен `.vscode/mcp.http.example.json`. Инструкции и сценарии: [agent.md](docs/agent.md), [demo.md](docs/demo.md).

## Политика записи

Запись по умолчанию отключена. Для разрешения операций в `/demo/` оператор задаёт `IACPAAS_ALLOW_WRITES=1` и `IACPAAS_WRITABLE_PREFIX=/demo/`. CLI дополнительно запрашивает подтверждение пользователя; неинтерактивный режим отказывает в изменении.

MockBackend хранит изменения в памяти процесса. После перезапуска восстанавливаются исходные данные. Серверная политика действует независимо от настроек и инструкций агента.
