# IACPaaS MCP

Самостоятельный MCP-сервер, собственный агентный цикл и веб-чат для технологических газов и связанных инфоресурсов IACPaaS.

| Часть | Исходники | Назначение |
|---|---|---|
| MCP-сервер | [src/iacpaas_mcp](src/iacpaas_mcp) | JWT, чтение платформы, графовые инструменты, stdio/HTTP |
| Агент | [src/standalone_agent](src/standalone_agent) | Модель → MCP → источники → проверка и исправление ответа |
| Веб-чат | [src/gas_web](src/gas_web), [frontend](frontend) | Интерфейс, HTTP/SSE, настройки и полная история SQLite |

По умолчанию подключается **реальная IACPaaS в режиме чтения**. Нужны учётные данные и доступ к ресурсам. Ошибки не включают mock; запись в реальные ресурсы запрещена. `IACPAAS_BACKEND=mock` явно выбирает синтетический стенд. Режим агента `demo` — сценарный парсер без LLM, а не источник реальных ответов.

## Веб-чат без Docker

Установите Git и [uv](https://docs.astral.sh/uv/getting-started/installation/), откройте терминал в корне репозитория:

```sh
uv sync --frozen
```

Если `.env` ещё нет, скопируйте `.env.example`: в Linux/macOS — `cp .env.example .env`, в PowerShell:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

Запуск одинаков для этих систем:

```sh
uv run --frozen --env-file .env iacpaas-web --host 127.0.0.1 --port 8080
```

Откройте [http://127.0.0.1:8080](http://127.0.0.1:8080). В настройках:

1. Выберите OpenRouter, OpenAI API, свой OpenAI-совместимый API или отдельный профиль Codex. Укажите модель и нужные данные подключения. [Настройка провайдеров](docs/model-providers.md).
2. Введите логин и пароль IACPaaS, проверьте пути баз и онтологий. Восемь типовых путей в «Загрузки» заполнены заранее; их можно изменить и сохранить без перезапуска. [Подключение платформы](docs/connect-iacpaas.md).
3. «Проверить доступ» читает все указанные ресурсы без модели. «Проверить подключение» модели выполняет запрос провайдеру и может расходовать его лимит.

Полная история, источники и версии диалога сохраняются в SQLite. При заполнении рабочего контекста агент сжимает его отдельно от видимой истории. Проверка ответа возвращает автору замечания для ограниченных раундов исправления. Подробности: [устройство веб-чата](docs/web.md), [действия интерфейса](docs/interface.md).

На Windows нужны Git и `uv` в `PATH`; Docker и WSL для прямого запуска не требуются. При необходимости установите их через `winget install --id Git.Git -e --source winget` и `winget install --id astral-sh.uv -e --source winget`, затем откройте новый терминал. Остановка сервера — `Ctrl+C`.

## Веб-чат в Docker

После создания приватного `.env`:

```sh
docker compose --env-file /dev/null up -d --build
```

В PowerShell используйте `--env-file NUL` вместо `/dev/null`. Файл `.env` монтируется как secret при запуске, а данные сохраняются в томе. Контейнер включает веб, агента и дочерний MCP; независимый запуск MCP остаётся доступен.

[Управление, резервные копии и LAN](docs/docker.md). Изменения приватного `.env` или обновление проекта не заменяют сохранённые пользовательские профили веб-чата. Если в старой `.env` явно остался `IACPAAS_BACKEND=mock`, смените его на `iacpaas` и перезапустите приложение.

## Самостоятельный MCP и VS Code

Внешний клиент использует собственное окружение, а не настройки браузерного профиля. Задайте `IACPAAS_USERNAME`, `IACPAAS_PASSWORD` и при необходимости пути в приватном `.env`:

```sh
# stdio: процесс запускает MCP-клиент
uv run --frozen --env-file .env iacpaas-mcp

# отдельный HTTP-сервер; MCP_HTTP_TOKEN должен быть настроен
uv run --frozen --env-file .env iacpaas-mcp --transport http --host 127.0.0.1 --port 8000
```

Для VS Code предусмотрены [.vscode/mcp.json](.vscode/mcp.json) и агент [IACPaaS Explorer](.github/agents/iacpaas.agent.md). Нужен чат-клиент с поддержкой MCP и доступом к модели. Запустите сервер через **MCP: List Servers** и проверьте фактические вызовы чтения, а не только статус запуска. [Порядок подключения и CLI-агент](docs/agent.md).

## Демо и проверки

Синтетические сценарии `/demo/university` требуют явного `IACPAAS_BACKEND=mock`: [команды для Bash и PowerShell](docs/demo.md). Они не проверяют доступ к газам IACPaaS.

Автоматические проверки без реальных ключей и ресурсов:

```sh
uv run --frozen ruff check .
```

Для тестов отключите автоматическое чтение личной `.env`:

```sh
PYTHON_DOTENV_DISABLED=1 uv run --frozen pytest -q
```

В PowerShell сначала выполните `$env:PYTHON_DOTENV_DISABLED = "1"`, затем `uv run --frozen pytest -q`.

Рабочий CI — [.github/workflows/test.yml](.github/workflows/test.yml). Тесты используют синтетические ресурсы и подставленные ответы внешних сервисов. Docker и зелёный CI не доказывают прохождения предметной или промышленной приёмки: [покрытие тестов](docs/verification.md), [критерии реального окружения](docs/acceptance.md).

## Навигация по репозиторию

```text
src/         три Python-компонента и поставляемая статика веба
frontend/    исходники и сборка компонентов JetBrains Ring UI
tests/       автоматические тесты; extended/ — разговорные и провайдерные регрессии
fixtures/    синтетические эталоны
docs/        тематическая документация, JSON Schema и синтетические примеры
.github/     действующий CI и инструкция агента VS Code
.vscode/     конфигурации подключения MCP
```

Файлы `ring.js`, `ring.css`, шрифты и лицензии в `src/gas_web/static` — поставляемые ресурсы интерфейса; сборка находится в `frontend`. `uv.lock` и `frontend/package-lock.json` фиксируют зависимости. Личные `.env`, базы, экспорты, отчёты и трассы не публикуются.

Все технические разделы и правила их обновления собраны в [docs/README.md](docs/README.md).
