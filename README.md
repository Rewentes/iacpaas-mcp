# IACPaaS MCP: сервер и агент

Учебный проект для команды из трёх человек. Один MCP-сервер, общий слой работы с графами и два клиента: Python CLI и агент VS Code.

> **Текущая версия автономная:** графовые данные синтетические (`mock`), реальная IACPaaS ещё не подключена по договорённости. Режим модели `demo` — сценарная заглушка, а не LLM. Реальный LLM-профиль предусмотрен отдельно. Результаты тестов не подменяют проверку платформы и IDE.

## Быстрый запуск

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/getting-started/installation/).

```sh
git clone https://github.com/Rewentes/iacpaas-mcp.git
cd iacpaas-mcp
uv sync --frozen
uv run --frozen iacpaas-agent "найди университет и покажи метаданные" --model demo --trace traces/demo.jsonl
```

Доступ к приватному репозиторию получают приглашённые collaborators. В режиме stdio агент сам запускает MCP-сервер: второй терминал не требуется.

Не нужны API-ключи IACPaaS или LLM. Не записывайте реальные секреты в команды, которые попадут в историю терминала/скриншоты.

## Проверки

```sh
uv run --frozen ruff check .
uv run --frozen pytest -q
```

Фактические результаты интеграционного прогона и непроверенные части описаны в [docs/verification.md](docs/verification.md). Для автоматизации на GitHub подготовлен [шаблон CI](ci/README.md); удалённый CI не объявляется выполненным.

## Отдельный запуск сервера

```sh
# Локальный stdio. Ожидает MCP-сообщения; это не обычная командная строка.
uv run --frozen iacpaas-mcp

# HTTP: сначала экспортируйте MCP_HTTP_TOKEN в окружение.
uv run --frozen iacpaas-mcp --transport http --host 127.0.0.1 --port 8000
```

Для HTTP используйте случайный `MCP_HTTP_TOKEN`. Он проверяется сервером. Не публикуйте этот учебный HTTP-сервер в интернет.

```sh
# Во втором терминале, с тем же MCP_HTTP_TOKEN:
uv run --frozen iacpaas-agent "посчитай граф /demo/university" \
  --model demo --transport http --url http://127.0.0.1:8000/mcp
```

Подробности аргументов: `uv run --frozen iacpaas-mcp --help` и `uv run --frozen iacpaas-agent --help`.

## VS Code

1. Установите зависимости командой `uv sync --frozen` и откройте корень репозитория в VS Code.
2. Конфигурация stdio находится в `.vscode/mcp.json`. Проверьте доверие серверу и доступ к выбранной модели в вашей установке VS Code.
3. Выберите custom agent из `.github/agents/iacpaas.agent.md`.
4. Выполните три сценария из [docs/demo.md](docs/demo.md).

HTTP-конфигурация дана отдельным примером `.vscode/mcp.http.example.json`. Она не запускает второй сервер сама. Не заменяйте текущую конфигурацию, не прочитав [docs/agent.md](docs/agent.md).

**Конфигурации подготовлены, но GUI VS Code на этом сервере не проверен.** Для итоговой сдачи нужен ручной прогон непосредственно в IDE.

## Реальная LLM

Скопируйте `.env.example` в `.env` и заполните `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL` для своего OpenAI-совместимого API, поддерживающего tool calling. Файл `.env` **не загружается приложениями автоматически**. Передайте его явно через uv:

```sh
uv run --frozen --env-file .env iacpaas-agent "найди университет и покажи метаданные" --model openai
```

Точно так же `--env-file .env` можно добавить при запуске HTTP-сервера и его клиента вместо экспорта переменных в shell. Инструкция и ограничения находятся в [docs/agent.md](docs/agent.md).

Без этих настроек live-модель не вызывается и не заменяется молча демонстрационной. Платные запросы запускайте осознанно.

## Запись

По умолчанию сервер запрещает изменение. Оператор может разрешить учебную запись через `IACPAAS_ALLOW_WRITES=1` и ограничить её префиксом `IACPAAS_WRITABLE_PREFIX=/demo/`. CLI дополнительно спрашивает пользователя; неинтерактивный запуск отказывает.

Это явный серверный **policy gate**, а не сервис одноразовых одобрений. Доступ к разрешённому серверу означает доверие клиенту в пределах политики. Для реальной платформы потребуется отдельная проверка прав и политики безопасности.

MockBackend изменяет только память процесса. Перезапуск восстанавливает фикстуру. Разные stdio-процессы не разделяют состояние.

## Работа команды

Один общий репозиторий. Для отдельной задачи создавайте ветку и небольшой pull request. В описании указывайте, что изменилось, как запустить и что проверено. Изменение схем инструментов согласуют все владельцы; вместе с ним обновляются примеры и тесты.
