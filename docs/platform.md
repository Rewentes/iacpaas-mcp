# Графовые ресурсы и backend

## Что действительно подключено

Реализован **MockBackend**, а не реальный API IACPaaS. Все данные синтетические.
Файл `src/iacpaas_mcp/data/demo.json` — внутренний нормализованный формат
`normalized-demo-v1`; он **не является** universal/meta/simple форматом платформы.
Универсальный парсер не заявлен и не реализован. Неизвестный формат отвергается.
Запрос `GraphService(backend="iacpaas")` завершится `unsupported_backend`, без
скрытого переключения. Нет HTTP-запросов, учетных данных или проверки реальной платформы.

## Граница интеграции

```python
from iacpaas_mcp.adapters import MockBackend
from iacpaas_mcp.domain import GraphService, DomainError

service = GraphService()  # новый изолированный mock
custom = GraphService(MockBackend("fixtures/my-normalized-resource.json"))
```

`Backend` — синхронный Protocol с `catalog() -> list[dict]`,
`get(path: str) -> dict`, `save(resource: dict) -> None`.
`get` отсутствующего ресурса выбрасывает `KeyError`; сервис превращает его в
`DomainError("not_found", message, retryable=False)`. Методы возвращают копии:
изменение прочитанного словаря не меняет хранилище. `save` также копирует вход.
Неудачное чтение fixture не подменяется стандартной fixture. Один backend хранит
ресурсы только в памяти; новый экземпляр начинает с исходного файла.

Для реальной интеграции отдельно потребуются документированный контракт платформы,
авторизация, адреса, преобразование настоящих экспортов, ошибки и проверка на стенде.
Это не означает, что текущий mock совместим с реальной платформой.

## Сервисный контракт

Все девять методов из IMPLEMENTATION_AGREEMENT синхронные. Ошибки — DomainError
с полями `code`, `message`, `retryable`.

- `list_inforesources(filter="", limit=100)`: `resources: [{path,name}]`;
  поиск подстроки по имени/пути без учета регистра. `complete=false` всегда:
  каталог ограничен конфигурацией, а не является полным каталогом платформы.
- `get_inforesource(path)`: метаданные `path`, `name`, `format`, `node_count`,
  `edge_count`; сам граф не включается.
- `get_subgraph(path, root="root", depth=2, max_nodes=2000)`:
  `nodes`, `edges`, `root`, `depth`, `complete`, `scope`, `warnings`.
- `count_graph(path, root=None, depth=None)`:
  числовые **`vertices`, `edges`** и совместимые с ними `node_count`, `edge_count`,
  отдельно `external_edge_count`. Без root/depth считает весь локальный ресурс,
  включая изолированные вершины. Только root — все достижимые локальные вершины,
  без ограничения глубины; depth без root использует `root`.
- `query_graph(path, field="name", value="", limit=100)`: `nodes`,
  `total_matches`, `complete`; локальный поиск подстроки без учета регистра.
  Допустимы id/name/metatype/value/comment/mark; `value` ищется по строковому
  представлению значения Python, это не графовый язык запросов и не JSONPath.
- `validate_resource(payload)`: `valid=true`, формат и контрольные количества;
  при ошибках выбрасывает `invalid_data`, а не возвращает ложный успех.
- `update_concept(path, concept_id, mark=None, comment=None)`: обновляет только
  указанные поля; `None` означает «оставить», пустая строка очищает текст.
  Возвращает `concept`, `path`; данные повторно валидируются до сохранения.
- `import_inforesource(payload, clear_if_exists=False)`: проверка, затем создание;
  существующий путь без явно переданного true отвергается `invalid_data`.
  При true ресурс полностью заменяется, а не сливается. Возвращает `path`, `replaced`.
- `export_inforesource(path)`: сам нормализованный ресурс, пригодный для повторного
  импорта. Не оборачивается дополнительным `resource`. Нет автоматической
  конвертации в реальные экспортные форматы.

Чтения возвращают `mock=true`, `complete`, `scope`, `warnings`;
исключение — экспорт, который является самим документом с `mock=true`.
Обертка MCP добавляет свой envelope и ограничения байтов. Записи помечены
`scope=volatile_mock_write` и предупреждением о непостоянстве.

## Нормализованная схема

Поля ресурса: `format="normalized-demo-v1"`, `mock=true`, абсолютный нормализованный
`path`, непустое `name`, `nodes`, `edges`. Неизвестные поля запрещены, приведение типов
не производится. Отвергаются не-JSON значения, NaN/Infinity, повторяющиеся id и
ребра с отсутствующим локальным source. Внешний target разрешен.
Вершина: обязательные id/name/metatype; необязательные value (JSON, по умолчанию null),
comment (строка), mark (строка либо null). Ребро: source/target/relation.
Необязательные отсутствующие поля сохраняют отсутствие при экспорте.

Ресурс содержит 1..2000 вершин и до 10000 экземпляров ребер. Непустые текстовые
поля ограничены 4096 символами, comment — 16384, path — 1024.
Сервис проверяет depth=0..5, max_nodes=1..2000 и limit=1..2000; bool вместо int
отвергается. MCP может вводить более строгие ограничения.

## Точная семантика графа и эталоны

BFS по исходящим ребрам, с visited; depth — число переходов, root имеет глубину 0.
Порядок детерминирован порядком исходных ребер. Цикл не создает бесконечного обхода.
В подграф включены локально выбранные вершины и **все экземпляры** ребер между ними,
плюс исходящие из выбранных вершин ребра к внешним target. Ребра к локальным
вершинам за границей выборки исключены. Внешние цели никогда не загружаются,
не входят в число вершин, но их ребра входят в `edges`/`edge_count`.
Два одинаковых ребра считаются дважды; ребро цикла также считается.

`complete=true` означает полноту **заявленной локальной области**, не платформы
и не внешних ресурсов. Ограниченная depth выборка полна относительно depth.
При отсечении max_nodes — `complete=false` и предупреждение.

| Область synthetic `/demo/university` | Вершины | Ребра |
|---|---:|---:|
| Весь ресурс | 5 | 6 |
| Достижимые из root | 4 | 6 |
| depth=0 | 1 | 0 |
| depth=1 | 2 | 2 |
| depth=2 | 3 | 4 |
| depth=3 или 5 | 4 | 6 |

В целом ресурсе одно внешнее ребро, одна изолированная вершина, пара одинаковых
ребер и цикл. `fixtures/mock-reference-counts.json` хранит проверяемые эталоны.

## Защита работы: зона роли 1

«Я отвечаю за предметные операции и адаптер хранилища: отделил транспорт от графа,
проверил семантику обхода на цикле, повторных ребрах и внешней ссылке, ограничил
схему и показал воспроизводимые эталоны. Это локальный mock, не завершенная
интеграция IACPaaS. Для ее подключения понадобится отдельный проверенный адаптер».

Это описание роли в проекте, не утверждение о реальном составе команды.
Политика разрешения записей, блокировки и аудит принадлежат серверному слою;
сам GraphService — внутренний API без пользовательской авторизации. Не следует
напрямую выставлять его наружу вместо серверной policy. MCP-сервер проверяет доступ,
а клиентский цикл обеспечивает подтверждение пользователя; эти проверки не дублируются в доменном слое.
