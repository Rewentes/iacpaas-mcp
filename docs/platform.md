# Графовые ресурсы и адаптеры

## Источники данных

`GraphService` выполняет операции над графом независимо от MCP-транспорта. Реализованы два адаптера:

| Адаптер | Данные и формат | Изменения |
|---|---|---|
| `IACPaaSBackend` | Реальная IACPaaS: вход по логину/паролю, приватный JWT, universal-экспорт → `normalized-iacpaas-v1` | Запрещены |
| `MockBackend` | Синтетическая фикстура `src/iacpaas_mcp/data/demo.json`, формат `normalized-demo-v1` | Только память процесса при разрешённой серверной политике |

MCP-сервер и веб-приложение по умолчанию выбирают **реальную IACPaaS**. Mock включается явно через `IACPAAS_BACKEND=mock` или `iacpaas-mcp --backend mock`. Ошибка входа, пути или сети не переключает источник на синтетические данные.

Настройка учётных данных, баз и онтологий: [подключение IACPaaS](connect-iacpaas.md). HTTP-контракт платформы, нормализация и ограничения адаптера: [интеграция](iacpaas-integration.md).

## Внутренний интерфейс

`Backend` — синхронный Protocol с методами `catalog()`, `get(path)` и `save(resource)`. Внутренний сервис получает экземпляр адаптера:

```python
from iacpaas_mcp.domain import GraphService
from iacpaas_mcp.platform import IACPaaSBackend
from iacpaas_mcp.adapters import MockBackend

native_service = GraphService(IACPaaSBackend.from_env())
demo_service = GraphService(MockBackend())
```

Первый вариант требует учётных данных в окружении. Конструктор адаптера проверяет конфигурацию; вход и загрузка происходят при чтении. Внутренний `GraphService()` без аргумента по совместимости создаёт mock, но фабрика запуска `server.create_service()` выбирает источник из конфигурации с default `iacpaas`. Передача строки `GraphService("iacpaas")` не создаёт реальный адаптер: нужно передать его экземпляр.

`MockBackend.get()` возвращает копию данных, `save()` сохраняет копию входа. Новый экземпляр заново загружает фикстуру. Реальный адаптер возвращает копию нормализованного экспорта, использует ограниченный кэш внутри процесса и всегда отклоняет `save()`.

Неизвестный mock-путь превращается из `KeyError` в `DomainError("not_found", ...)`. Реальный адаптер возвращает собственные `DomainError` для конфигурации, авторизации, прав, сети и формата. Ошибка содержит `code`, `message`, `retryable`.

## Операции и форматы

Читающие операции — каталог, метаданные, поиск, подграф, подсчёт, экспорт и проверка структуры. Для реального источника MCP дополнительно предоставляет `get_gas_specification`: извлечение нормативных границ состава газа. Точные аргументы и результаты перечислены в [контракте инструментов](contract.md).

`query_graph` поддерживает `auto`, `exact`, `contains`. В `auto` поля `id` и `metatype` сопоставляются точно, остальные — по подстроке без учёта регистра. Это поиск по экспортированным вершинам, а не графовый язык запросов. `total_matches` относится к условиям текущего запроса.

| Формат | Назначение и пределы |
|---|---|
| `normalized-demo-v1` | Синтетический граф: 1–2000 вершин, до 10000 экземпляров дуг |
| `normalized-iacpaas-v1` | Нормализованный universal-экспорт: до 50000 вершин, 200000 вхождений, глубина исходного дерева до 128 |

Вершины сохраняют идентификаторы, имена, типы и значения; дуги связывают source/target. Реальный формат также сохраняет метапонятия, комментарии, ссылки, клоны и `source`. Он не является исходным universal JSON и не заявляет поддержку всех форматов IACPaaS. `validate_resource` проверяет структуру нормализованного графа, а не все предметные правила онтологии.

`export_inforesource` возвращает сам нормализованный документ. Повторный импорт предусмотрен только для `normalized-demo-v1` в mock. Реальный экспорт нельзя записать обратно этим инструментом.

## Обход, полнота и подсчёт

Обход выполняется BFS по исходящим дугам с множеством посещённых вершин. `depth` — число переходов, корень имеет глубину 0. Порядок определяется исходными дугами; цикл не создаёт бесконечного обхода.

В подграф входят выбранные локальные вершины и все экземпляры дуг между ними, а также дуги от выбранных вершин к внешним целям. Дуги к локальным вершинам за пределами выборки не включаются. Внешние цели автоматически не загружаются и не считаются локальными вершинами; их дуги учитываются. Повторные дуги не сливаются.

`count_graph` без `root`/`depth` считает весь экспорт, включая изолированные вершины. С `root` — достижимую область, с `depth` — область заданной глубины. Публичные подграфы ограничены 2000 вершинами и глубиной 0–5.

`complete=true` означает полноту заявленной локальной области, а не всего фонда IACPaaS или внешних ресурсов. Каталог ограничен настройкой и всегда имеет `complete=false`; при ограничении поиска или обхода причина указывается в `warnings`.

Эталоны относятся только к синтетическому `/demo/university`:

| Область | Вершины | Дуги |
|---|---:|---:|
| Весь ресурс | 5 | 6 |
| Достижимые из root | 4 | 6 |
| depth=0 | 1 | 0 |
| depth=1 | 2 | 2 |
| depth=2 | 3 | 4 |
| depth=3 или 5 | 4 | 6 |

Они хранятся в [фикстуре счётчиков](../fixtures/mock-reference-counts.json) и проверяются тестами. Это не количества объектов реальной платформы.

## Изменения и ответственность слоёв

`update_concept` меняет только переданные `mark`/`comment`, а `import_inforesource` создаёт или явно заменяет mock-ресурс. Изменения исчезают при перезапуске. Сервер проверяет разрешённый префикс и флаг записи; CLI отдельно требует подтверждение человека. Для IACPaaS запись запрещена и в сервере, и в доменном слое, и в адаптере.

`GraphService` — внутренний API без пользовательской аутентификации. Его нельзя выставлять наружу вместо защищённого MCP-слоя. Политика доступа описана в [документации сервера](server.md), границы готовности — в [статусе компонентов](status.md).
