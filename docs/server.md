# MCP-сервер

## Что реализовано

`server.py` — фабрика `create_server(service=None, ...)` на официальном `mcp==1.30.0` FastMCP и CLI. Девять инструментов повторяют интерфейс `GraphService`: каталог, метаданные, подграф, подсчёт, поиск, валидация, экспорт, изменение концепта, импорт. Это **локальный mock**, а не подключение к IACPaaS. Импорт/экспорт работают только с внутренним форматом `normalized-demo-v1`; универсальный/нативный формат платформы не поддерживается.

`schemas.py` — Pydantic-модель `ToolResponse` и ограничения аргументов. FastMCP публикует `inputSchema`, `outputSchema` и аннотации инструментов. Успех имеет `ok=true`, `data`, `backend="mock"`, `complete`, `warnings`. Поля полноты/предупреждений переносятся из домена; неполный конфигурационный каталог не выдаётся за полный каталог платформы.

`policy.py` — неизменяемая политика, прочитанная из окружения при создании сервера. Условие записи находится внутри обработчиков, поэтому прямой `call_tool` тоже не обходит запрет. Аннотации MCP сами по себе **не являются** защитой.

## Запуск

Из корня проекта после установки проекта и зависимостей (`uv sync --frozen`):

```bash
uv run --frozen iacpaas-mcp
# эквивалентный модуль; stdio по умолчанию
uv run --frozen python -m iacpaas_mcp.server --backend mock
```

Для разработки без установки самого пакета:

```bash
PYTHONPATH=src .venv/bin/python -m iacpaas_mcp.server
```

На stdout stdio-сервера находится только протокол MCP. Баннер mock и диагностика идут в stderr.

HTTP, в отдельном терминале:

```bash
# Значение берётся из вашего секретного хранилища/окружения, не из репозитория.
export MCP_HTTP_TOKEN='replace-with-local-random-secret'
uv run --frozen python -m iacpaas_mcp.server --transport http --host 127.0.0.1 --port 8000
```

Адрес — `http://127.0.0.1:8000/mcp`, заголовок клиента — `Authorization: Bearer <значение MCP_HTTP_TOKEN>`. Токен обязателен; сравнение выполняется `hmac.compare_digest`. Пустой токен, отсутствующий/неверный заголовок и дублирующиеся заголовки авторизации не предоставляют доступ. Проверка применяется к POST, GET и DELETE; до неё сессия не создаётся. Обёртка пропускает ASGI lifespan в FastMCP: менеджер сессий запускается и останавливается штатно. Публичный `server.streamable_http_app()` также защищён, а не только CLI.

По умолчанию разрешены только `127.0.0.1`, `localhost`, `::1`. `MCP_HTTP_ALLOW_REMOTE=1` — отдельный явный административный opt-in для другой привязки. Это не настройка промышленной публикации: нет OAuth, TLS, ролевой модели пользователей или заявления о соответствии OAuth. Оставляйте стенд локальным. Проверены IPv4 localhost и отказ для `0.0.0.0` без opt-in; IPv6 соединение не испытывалось.

**Окружение:** сервер не ищет и не загружает `.env` автоматически и не читает секреты из других каталогов. Передавайте переменные через shell `export`, конфигурацию доверенного процесса или окружение MCP host. Образец `.env` сам по себе не включает запись и не задаёт HTTP-токен запущенному процессу.

`--backend iacpaas` завершается с ошибкой `unsupported_backend`: нативный API не подключён. Тихого переключения на mock нет.

## Политика изменения данных

Оператор запуска может одновременно задать:

```bash
export IACPAAS_ALLOW_WRITES=1
export IACPAAS_WRITABLE_PREFIX=/demo/
```

Любое другое значение флага, отсутствующий prefix, `/` вместо prefix, путь вне `/demo/`, dot-сегменты, `%`-кодирование, обратный слеш и неканонические пути отклоняются. Политика сохраняется при старте; изменение `os.environ` после создания сервера не повышает права существующего экземпляра. `confirmed=true` или иной аргумент от модели не включает запись.

Это **серверный startup policy gate**, а не отдельная служба человеческого одобрения. Агент отдельно должен спрашивать человека перед каждым изменением; сервер не может доказать факт этого разговора. Когда оператор разрешил записи, любой клиент с доступом к этому серверу получает разрешённые mock-операции. Поэтому токен/stdio-доступ и startup environment доверяются оператору.

Изменения volatile: сохраняются в памяти одного экземпляра, исчезают при перезапуске. Один `RLock` сериализует mock-записи и чтение домена. Аудит `iacpaas_mcp.audit` записывает имя операции и итог без содержимого payload/comment и без токена. На уровне INFO его выводит логирование SDK; долговременное хранение журнала — задача запускающего процесса. Автоматических повторов нет.

## Ограничения и ошибки

- `depth`: 0..5; `max_nodes`: 1..2000; `limit`: 1..100.
- Непустые path/id ограничены 1024 символами, текстовые фильтры/изменения — 4096.
- По умолчанию JSON аргументов инструмента и компактный UTF-8 JSON успешного envelope ограничены каждый 1 MiB; фабрика позволяет менять бюджеты для тестов. Это не лимит полного wire frame: SDK добавляет JSON-RPC и совместимый текстовый дубль результата. Дополнительно действует стандартный лимит raw HTTP body SDK.
- Проверка схемы и аргументного бюджета происходит до вызова сервиса. До мутации резервируется ограниченное подтверждение. Если полный ответ применённой записи слишком велик, возвращается `ok=true`, `data={"applied":true,"result_omitted":true}`, `complete=false` с предупреждениями и audit success. Если подтверждение не помещается, операция отклоняется до изменения. Большие ответы чтения возвращают limit_exceeded. Это не устраняет неизвестный исход будущей сетевой записи: при таймауте сначала проверяйте состояние, не повторяйте автоматически.
- Ошибка выполнения возвращается как MCP `CallToolResult(isError=true)` с JSON-текстом `{code,message,retryable}`, без успешного `structuredContent`. Используется `ToolError` для текста; подкласс FastMCP снимает стандартную SDK-обёртку `Error executing tool ...`, чтобы JSON оставался машинно читаемым.
- Категории: `not_found`, `invalid_data`, `limit_exceeded`, `permission_denied`, `unsupported_backend`, `timeout`, `platform_error`. Последние две санитизируют внутреннее исключение. `unsupported_backend` сейчас проверяется в CLI, до запуска транспорта.
- `TimeoutError` классифицируется, но отдельного планировщика принудительного прерывания синхронных операций нет. Текущий backend локальный, сетевые вызовы отсутствуют. Нативный адаптер потребует собственных deadline, авторизации и интеграционных тестов.

## Что действительно испытано

Настоящие SDK `ClientSession` через in-memory streams, stdio-подпроцесс и TCP Streamable HTTP. Проверены tools/list, схемы, чтение, импорт и изменение с чтением назад, отказы policy, запрет включения policy после старта, HTTP 401 и создание/удаление сессии, штатный ASGI shutdown, сериализация параллельных direct calls, бюджеты и категории ошибок. Состояние интеграций описано в `status.md`, результаты проверок — в `verification.md`.
