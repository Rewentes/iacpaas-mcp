# Подключение IACPaaS

Read-only адаптер реальной платформы реализован. Настройка, HTTP-контракт, таблица операций MCP, проверки и ограничения находятся в [iacpaas-integration.md](iacpaas-integration.md).

Нужны логин, пароль и точные пути доступных ресурсов. Приложение получает JWT через вход и читает universal-экспорты. Реальная IACPaaS включена по умолчанию; отсутствие доступа и ошибки не подменяются mock-данными.

В веб-чате откройте **Настройки → Вход в IACPaaS → Ресурсы и онтологии**. Восемь типовых путей в папке «Загрузки» заполнены заранее: база газов и её онтология, база химических элементов и веществ, система единиц, онтология характеристик, база свойств материалов и её онтология, терминологический справочник. Для отдельной онтологии химических элементов предусмотрено дополнительное необязательное поле.

Проверьте расположение ресурсов в своём аккаунте, при необходимости измените поля и нажмите «Сохранить вход и ресурсы». Они применятся к следующему запросу без перезапуска. Пустое поле исключает ресурс из каталога агента. «Заполнить типовые пути» восстанавливает стандартные значения в форме; для применения нужно сохранить. Эта настройка не создаёт и не копирует ресурсы на платформе.

Самостоятельный MCP использует те же типовые пути. Свои пути можно задать в приватном `.env`, например:

```dotenv
IACPAAS_GASES_PATH="Загрузки / База технологических газов"
```

Путь должен точно соответствовать расположению базы относительно «Моего фонда» вошедшего пользователя. У этого аккаунта должны быть права на чтение ресурса. Значения `.env` используются в веб-чате до сохранения собственного профиля. После изменения `.env` перезапустите сервер; изменения через веб-настройки этого не требуют.

Кнопка «Проверить доступ» читает все настроенные ресурсы, включая онтологии, и сообщает об отдельных недоступных ресурсах. Успех означает, что прочитаны все указанные ресурсы. Ошибки входа, конфигурации, чтения и сети показываются раздельно; платная модель не вызывается.

Запись в реальные ресурсы отключена. Для будущей записи необходимы отдельная копия ресурса, проверка прав, явное подтверждение, контроль неизвестного исхода и read-back. Текущая политика записи относится только к volatile mock.
