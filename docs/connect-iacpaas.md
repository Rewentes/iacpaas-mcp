# Подключение IACPaaS

Read-only адаптер реальной платформы реализован. Настройка, HTTP-контракт, таблица операций MCP, проверки и ограничения находятся в [iacpaas-integration.md](iacpaas-integration.md).

Нужны логин, пароль и точные пути доступных ресурсов в приватном `.env`. Приложение получает JWT через вход и читает universal-экспорты. Используйте `IACPAAS_BACKEND=iacpaas`; отсутствие доступа и ошибки не подменяются mock-данными.

Веб-настройки сохраняют логин и пароль, но не заполняют пути ресурсов. В новой копии проекта задайте хотя бы один путь в `.env`, например:

```dotenv
IACPAAS_GASES_PATH="Загрузки / База технологических газов"
```

Это пример: путь должен точно соответствовать расположению базы относительно «Моего фонда» вошедшего пользователя. У этого аккаунта должны быть права на чтение ресурса. После изменения `.env` перезапустите сервер (при Docker — `docker compose restart web`). Остальные пути задаются аналогично по `.env.example`.

Кнопка «Проверить доступ» проверяет чтение первого настроенного ресурса. Ошибки конфигурации (HTTP 400), входа (401), прав (403), отсутствующего ресурса (404), соединения (502) и ожидания (504) показываются раздельно. Если пути не заданы, запрос на вход в IACPaaS ещё не выполняется.

Запись в реальные ресурсы отключена. Для будущей записи необходимы отдельная копия ресурса, проверка прав, явное подтверждение, контроль неизвестного исхода и read-back. Текущая политика записи относится только к volatile mock.
