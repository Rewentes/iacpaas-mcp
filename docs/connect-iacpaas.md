# Как позже подключить настоящую IACPaaS

Сейчас backend только тестовый. Ни ключи, ни URL сами по себе не включают ещё не реализованный адаптер.

## Последовательность

1. Получить доступ к безопасному тестовому ресурсу и отдельной копии для записи. Не использовать боевые данные.
2. По официальной документации и фактическому ответу подтвердить авторизацию, путь ресурса, параметры экспорта и коды ошибок.
3. Сохранить небольшой обезличенный настоящий экспорт и его эталонные вершины/дуги. Фикстуру явно отделить от синтетических demo-данных.
4. Реализовать backend с тем же интерфейсом чтения/сохранения, описанным в `platform.md`. Отдельный преобразователь должен проверять universal, пути от корня, ссылки, внешние ресурсы, типы значений и неполные экспорты.
5. Ввести предел загрузки **до** JSON-разбора, таймаут соединения/чтения и ограничение глубины. Не считать предел итогового MCP-ответа защитой от слишком большой загрузки.
6. Перевести ошибки платформы в DomainError без ключей/сырого HTML в сообщениях. Ошибку авторизации не исправлять переходом на mock.
7. Сопоставить каждый MCP tool с реальным REST-вызовом либо локальной операцией. Не считать Java-метод внутреннего API готовым внешним REST endpoint.
8. Выполнить те же MCP-контрактные проверки сначала на реальном чтении. Запись включать только после подтверждения прав и отдельной проверки на копии.
9. После записи сверить результат чтением. При таймауте отправленного изменения исход может быть неизвестен: не делать слепой retry.

## Что записать в таблицу соответствия

| MCP tool | Сейчас | После проверки API |
|---|---|---|
| list_inforesources | ограниченный каталог MockBackend | подтверждённый каталог из конфигурации или поддерживаемый механизм платформы |
| get_inforesource / get_subgraph / export_inforesource | внутренний синтетический граф | проверенный REST-экспорт и конвертация |
| count_graph / query_graph | локальный обход внутреннего графа | локальный обход проверенного полного/ограниченного экспорта |
| validate_resource | структурная проверка нормализованной модели | отдельная проверка нужного платформенного формата; не обещать полную онтологическую валидность |
| update_concept / import_inforesource | изменение памяти процесса | фактический API, права, policy gate и read-back |

Пути и методы из расширенного плана являются ориентиром, а не доказательством работающей интеграции. Точные параметры фиксируются после собственного прогона.
