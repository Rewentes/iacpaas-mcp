# Интерфейс чата

## Компоновка и оформление

История диалогов расположена слева, сообщения и ввод — по центру. Пустой чат показывает приветствие, поле ввода и два случайных примера из десяти фиксированных вопросов. Нажатие на пример заполняет поле ввода.

Провайдер, модель, API-ключ и вход IACPaaS находятся в настройках. Сохранённые секреты не возвращаются браузеру; поля пароля и ключа остаются пустыми. Проверка доступа к платформе читает один разрешённый ресурс без запроса к модели.

Контролы используют [JetBrains Ring UI](https://github.com/JetBrains/ring-ui), шрифт Inter загружается локально. Типографика и цвета заданы общими токенами. Доступны светлая, тёмная и системная темы с сохранением выбора браузером. Анимации учитывают `prefers-reduced-motion`.

Переписка и список диалогов прокручиваются отдельно. При чтении старых сообщений поступление ответа сохраняет позицию; к концу можно перейти кнопкой. На узком экране боковая панель открывается отдельно. Таблицы и длинные технические значения имеют внутреннюю горизонтальную прокрутку.

## Действия с сообщениями и диалогами

«Изменить запрос» открывает редактор; отправка создаёт новую ветку с сообщениями до выбранного вопроса. «Сгенерировать снова» создаёт новый ответ в отдельной версии. Исходные сообщения и источники сохраняются. Создание версии не вызывает модель; новый цикл начинается при её отправке. Автоматических платных повторов нет.

Меню «⋯» у диалога содержит «В архив» и «Удалить». Архив доступен отдельной кнопкой; восстановление возвращает диалог в активный список. Архивная история доступна для чтения. Удаление требует подтверждения и очищает только выбранный диалог, сохраняя отдельные версии. Во время незавершённого запроса эти действия блокируются.

Ход работы показывается по мере получения событий и сохраняется с ответом. Markdown выводится безопасными DOM-узлами: HTML модели не исполняется. Источники и отчёт автоматической сверки раскрываются отдельно; доступны полные результаты MCP и кликабельные ссылки, включая диапазоны свидетельств.

Контракт HTTP, хранение и рабочий контекст описаны в [web.md](web.md), профили модели — в [model-providers.md](model-providers.md).
