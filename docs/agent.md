# Собственный агент и VS Code

## Три способа подключения

| Клиент | Цикл и модель | Откуда берутся настройки |
|---|---|---|
| Веб-чат | `ConversationAgent`, выбранный провайдер | Изолированный профиль браузерного владельца; до сохранения — окружение сервера |
| Python CLI `--model openai` | Тот же `ConversationAgent`, OpenAI-совместимый API | Окружение и явно переданная `.env` |
| VS Code / другая MCP-оболочка | Собственный агент и модель оболочки | Её MCP-конфигурация и окружение, не профиль веб-чата |

MCP-сервер сам не вызывает модель. При stdio клиент запускает дочерний процесс, при HTTP подключается к отдельному серверу. Docker для самостоятельного MCP не требуется. Источник по умолчанию — реальная IACPaaS; синтетический `mock` включается явно.

## CLI с реальной моделью

В приватной `.env` задайте учётные данные IACPaaS и `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`. Endpoint должен поддерживать Chat Completions и tool calling. Установите зависимости через `uv sync --frozen`, затем:

```sh
uv run --frozen --env-file .env iacpaas-agent "Найди одну марку гелия и покажи её нормативные характеристики" --model openai
```

`OPENAI_BASE_URL` CLI принимает базовый адрес API, а не полный `/chat/completions`. Профили веб-чата на CLI не распространяются. Сам CLI не ищет `.env`; файл загружает `uv --env-file` или оболочка экспортирует значения заранее.

Общий цикл получает вопрос и контекст, вызывает read-only инструменты, формирует ответ, передаёт автору замечания и проверяет исправленный вариант. Число MCP-вызовов ограничено `--max-calls 1..12`; дополнительные чтения при исправлении используют оставшийся бюджет. Пояснения направляются в stderr, итог — в stdout. CLI запускает один запрос; постоянную историю пользовательских диалогов организует веб-слой. Подробности цикла: [архитектура](architecture.md), [верификация и контекст](web.md).

`--model demo` запускает ограниченный сценарный парсер без LLM. Для `/demo/university` также нужен явный `IACPAAS_BACKEND=mock`: [офлайн-примеры](demo.md). Эти два переключателя относятся к разным вещам: модели и источнику данных.

## VS Code

Нужны `uv` в `PATH`, поддерживающий MCP чат-клиент и доступ к его модели. Откройте корень проекта и выполните `uv sync --frozen`.

1. В локальной `.env` задайте `IACPAAS_USERNAME` и `IACPAAS_PASSWORD`; при необходимости измените пути ресурсов. [Подключение платформы](connect-iacpaas.md).
2. Просмотрите [.vscode/mcp.json](../.vscode/mcp.json): сервер `iacpaas` использует stdio, `uv run --frozen iacpaas-mcp`, рабочую папку проекта, `envFile` и запрет записи.
3. Через **MCP: List Servers** запустите `iacpaas`; при ошибке выберите **Show Output**. В чате выберите [IACPaaS Explorer](../.github/agents/iacpaas.agent.md) и разрешите его инструменты.
4. Попросите каталог, метаданные базы газов и её онтологии, затем характеристики одной марки. Раскройте реальные вызовы инструментов и проверьте `backend=iacpaas`, `mock=false`, `complete`, `warnings`.

`tools/list` и статус запуска подтверждают только подключение процесса; успешное чтение реальных ресурсов проверяется отдельно. Наличие конфигурации не означает наличия установленного Copilot или другого чат-клиента.

Файл использует формат VS Code `servers` с `envFile`. Другие оболочки могут ожидать `mcpServers` и не поддерживать загрузку файла окружения. Передавайте им окружение либо явную команду `uv run --frozen --env-file /полный/путь/.env iacpaas-mcp` с рабочей папкой проекта. Возможности конкретного клиента сверяйте с его документацией, не копируйте редакторские поля вслепую.

Для HTTP предусмотрен [.vscode/mcp.http.example.json](../.vscode/mcp.http.example.json). Это пример, не автоматически подключаемый второй сервер: замените stdio-конфигурацию и отдельно запустите сервер по [инструкции](server.md). Токен клиента должен совпадать с серверным `MCP_HTTP_TOKEN`. Поле `inputs` примера требует поддержки запросов ввода выбранным клиентом.

## Трассы и подтверждения

`--trace traces/session.jsonl` записывает события, аргументы, результаты и отчёт. Файл имеет ограничение размера, mode `0600`, перезаписывается при новом запуске; значения секретов маскируются. Это best-effort redaction, а не гарантия удаления неизвестного секрета в произвольном тексте. Личные трассы не публикуются; поставляемые JSON-примеры синтетические.

В рабочем модельном цикле запись в платформу не поддерживается. Демо-запись в память mock требует серверной политики и отдельного подтверждения человека в интерактивном CLI; `--non-interactive` запрещает её. VS Code использует свои разрешения инструментов. Инструкция агента не заменяет серверную политику. Подробности: [сервер](server.md), [синтетические сценарии](demo.md).
