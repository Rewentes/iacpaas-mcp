# Веб-приложение

## Запуск

Приложение также запускается в Docker: [команды и постоянное хранилище](docker.md). CLI принимает `--env-file` для приватной конфигурации без подстановки переменных и повторяемый `--trusted-host` для точных разрешённых адресов. В контейнерном режиме список можно задать через `IACPAAS_TRUSTED_HOSTS`.

```sh
uv sync --frozen
# Создайте локальный .env по образцу .env.example, если его ещё нет.
uv run --frozen --env-file .env iacpaas-web --host 127.0.0.1 --port 8080
```

Веб-чат: `http://127.0.0.1:8080`. Путь SQLite можно передать через `--db`. Не помещайте базу с реальной перепиской в Git или публичный статический каталог. Перезапуск приложения не должен менять владельца браузерной сессии или удалять её диалоги.

Для модели используются `OPENROUTER_API_KEY` и `OPENROUTER_MODEL` (по умолчанию `deepseek/deepseek-v4.1-flash`). Ключ OpenRouter отличается от авторизации Hermes и токена платформы IACPaaS. Отсутствующий ключ не включает демонстрационную модель автоматически.

Профиль существующего CLI с `--model openai` настраивается отдельно переменными `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`. Для воспроизводимого запуска `.env` передаётся явно через `uv --env-file`; веб-CLI также вызывает `python-dotenv`, не переопределяя уже заданное окружение.

## Границы компонентов

```text
Браузер → HTTP API приложения → ConversationAgent → MCP → IACPaaS backend
                  │                    │
                  └─ SQLite            └─ OpenRouter / DeepSeek
```

Backend хранит полный диалог и управляет принадлежностью сессии; агент собирает рабочий контекст и возвращает результат вместе с источниками, статусом верификации и обновлением резюме. Браузер не получает ключ модели или JWT платформы и не вызывает инструменты непосредственно.

## HTTP-контракт

Запросы выполняются с того же origin. `GET /api/me` устанавливает HttpOnly cookie анонимного пользователя и возвращает CSRF-токен. Это локальная браузерная идентичность, не полноценная система аккаунтов. Изменяющие операции передают токен в `X-CSRF-Token`; `user_id` из JSON не является авторизацией.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/me` | Идентичность браузера, CSRF, имя модели и backend |
| GET | `/api/conversations` | Свои диалоги |
| POST | `/api/conversations` | Новый диалог, тело `{"title":"Новый диалог"}` |
| GET | `/api/conversations/{id}/messages` | Сообщения и сведения о контексте; `limit` и `before` для старых страниц |
| POST | `/api/conversations/{id}/messages` | Запрос агенту: `{"content":"…","request_id":"…"}` |

`request_id` сохраняется при повторе одной и той же отправки: повтор не должен вызывать модель заново. Изменение текста при том же идентификаторе — конфликт. Чужой и неизвестный диалог не различаются по доступности: оба возвращают 404.

Структура сообщения: `id`, `role`, `content`, `created_at`, `state`, `sources`, `verification`. Состояние сообщения: `pending`, `complete` или `failed`. Новая страница истории возвращает сообщения от старых к новым, `has_more` и `next_before`.

Ошибка имеет неуспешный HTTP-код и форму `{"error":{"code":"…","message":"…","retryable":false}}`. Сообщение пользователя сохраняется даже при ошибке провайдера. Нельзя повторять запись в платформу только потому, что транспорт не вернул ответ.

## Разговорный цикл и ход работы

`ConversationAgent` реализует собственный цикл без LangChain: модель выбирает чтение MCP, получает результат и решает, нужно ли ещё чтение или уже можно ответить. Инструкции находятся в `src/standalone_agent/prompts.py`. Намерение определяет модель по инструкциям: сначала различить объяснение метода, фактический запрос и продолжение разговора; только затем решать о чтении MCP. Для методических вопросов промпт запрещает поиск произвольных газов. Готовых ответов и веток по совпадению пользовательской фразы нет. Ответ формулирует выбранная модель. Контекст истории помогает разрешать продолжения вопроса, но не считается подтверждением актуальных значений платформы.

Перед работой приложение сообщает о начале обработки. Модель может дать короткое пояснение вместе с вызовом инструмента; приложение передаёт его и события начала/окончания чтения в браузер. Это публичные пояснения действий и результатов; отдельные поля внутреннего рассуждения провайдера не показываются. Итог формулирует модель, используя Markdown и ссылки на evidence текущего хода. Браузер отображает ограниченное подмножество Markdown через DOM без исполнения HTML.

Для живых обновлений POST сообщений принимает `Accept: text/event-stream`. Событие `progress` содержит `kind` и `text`, `done` — `status` и исходный JSON-результат. При ошибке после начала потока HTTP-код самого потока остаётся 200; код результата находится в `done.status`. Служебные комментарии поддерживают соединение. Без этого заголовка контракт остаётся JSON. Повтор завершённого запроса возвращает сохранённый JSON, не запускает модель снова. Разрыв соединения не вызывает автоматическую повторную отправку.

Ход работы сохраняется в `verification.progress` вместе с итоговым сообщением. После перезагрузки он доступен в раскрывающемся разделе ответа. Кнопки источников открывают соответствующие записи внутри сообщения. Изменение вопроса и перегенерация сохраняют прежнюю ветку диалога.

## Верификация

Основной формат ответа модели — обычный русский Markdown со ссылками `[e1]` у фактов. Для пояснения метода и беседы ссылки не обязательны. Дополнительно поддерживается структурированный формат `{"type":"answer","intent":"data","text":"Ответ [e1]","source_ids":["e1"]}`; другие намерения — `guidance`, `conversation`, `clarification`. Отсутствие JSON-обёртки у нормального текста не является ошибкой. Источники регистрирует приложение по фактическим MCP-результатам текущего хода. Неизвестные ID отклоняются. Явные физические величины (число вместе с единицей) сопоставляются с выбранными свидетельствами. Нумерация списков не считается измерениями; отдельные числа, количества и номера документов передаются смысловой проверке, а не отклоняются автоматически по глобальному набору цифр. При отказе сохраняются исходный очищенный черновик и конкретная диагностика.

После первичной сверки ссылок и чисел выполняется проверка смысла ответа:

1. Код проверяет явные числовые нормативные утверждения: единицу и направление границы рядом с цитатой. Подмена «не менее» на «не более», потеря границы или неверная единица останавливают публикацию до проверочного обращения к модели.
2. Отдельный запрос к модели получает вопрос, последние сообщения, рабочую сводку и выбранные свидетельства и полные MCP-документы с контекстом газа и происхождением данных. Он проверяет все утверждения каждого смыслового блока: газ/сорт, компонент, числа, единицы, норматив или измерение, полноту и соответствие вопросу.
3. Приложение требует отчёт по каждому блоку без пропусков и повторов, проверяет ID источников. Блок с цитатой нельзя объявить не содержащим фактов. Верные факты, не отвечающие на вопрос, также отклоняются.
4. Если часть блоков подтверждена и отвечает на вопрос, публикуется только она с отметкой «Частичный ответ». Если ничего существенного не подтверждено, отчёт неполон, произошёл таймаут или не хватило контекста, подготовленный вывод не публикуется. Источники и результат проверки сохраняются. Автоматического повторного платного запроса нет.

Успешный связный ответ получает `reviewed` («Сверено по источникам»). В раскрывающемся разделе видны проверенные блоки и основания. Сверка остаётся автоматической и может ошибаться; она не заменяет первоисточник или экспертную оценку.

Проверка добавляет один вызов модели к предметному ответу. Для пояснений без фактов платформы она не нужна. В OpenRouter параметры служебной обработки выбираются по публичным возможностям модели: поддерживаемый `low`, затем `minimal`, либо отключение только при явной поддержке и отсутствии обязательного режима. Настройки основного ответа не меняются. Каталог возможностей кешируется на 15 минут. Причина: внутренние токены модели могут исчерпать общий выходной бюджет до появления отчёта — см. [документацию OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens).

Старые форматы `source_ids` без текста и `claims` принимаются для совместимости. Они сохраняют точную сверку исходных полей, но также проходят проверку смысла и соответствия вопросу. Обойти её выбором старого формата нельзя.

Статусы:

- `reviewed` — текст прошёл сверку источников, чисел и проверку смысловых блоков;
- `verified` — совместимый программный вывод полей, также прошедший проверку блоков;
- `grounded` — промежуточный результат сверки ссылок/чисел и прежние сохранённые ответы;
- `rejected` — обнаружена неподтверждённая величина или смысловое противоречие в подготовленном ответе;
- `review_unavailable` — проверка не завершилась, это не отсутствие данных пользователя;
- `insufficient_data` — для предметного ответа нет подтверждающих источников;
- `not_applicable` — пояснение, беседа или уточнение без утверждений о данных платформы;
- `error` — ошибка выполнения или неизвестные источники.

Резюме старой переписки не заменяет первичный источник. Отсутствие данных, ограниченная область чтения и недоступность платформы — разные случаи.

## Контекст и полная история

Полная история сохраняется для пользователя. Модели передаются инструкции, схемы tools, резюме покрытой старой части и свежие сообщения. При достижении бюджета старая завершённая часть сжимается вызовом модели; отдельно сохраняются текст резюме и `covered_through_message_id`. Повторное сжатие не удаляет исходные сообщения и не должно дублировать уже покрытую часть в контексте.

Показатель токенов является оценкой, если явно не используется tokenizer выбранного провайдера. Нужно оставлять запас под ответ и инструментальные результаты. Заявленный провайдером максимальный контекст не является рекомендуемым размером каждого запроса.

Настройки: `AGENT_CONTEXT_LIMIT=48000`, `AGENT_OUTPUT_RESERVE=4096`, `AGENT_TOOL_RESULT_BYTES=8192`, `AGENT_SUMMARY_BYTES=2048`. Оценка основана на UTF-8-размере и служебном запасе, не на точном tokenizer. Размер резюме ограничен байтами. `MCP_TRANSPORT=stdio` запускает локальный MCP; для HTTP используются `MCP_TRANSPORT=http`, `MCP_URL` и `MCP_HTTP_TOKEN`.

## Ограничения

- Начальный bind — localhost; разрешены Host `localhost`, `127.0.0.1` и `[::1]`. При запуске с конкретным IP в `--host` этот IP также добавляется в разрешённые Host; `0.0.0.0` и `::` не включают wildcard-доверие. Чужой Host отклоняется до создания браузерной сессии. Приложение не следует напрямую публиковать в интернете.
- Веб-агент не выполняет изменяющие MCP-инструменты в начальной конфигурации.
- `IACPAAS_BACKEND=iacpaas` включает read-only доступ к настроенным реальным ресурсам; `mock` оставляет синтетические данные. Источник и время выгрузки сохраняются в MCP-результатах. Подробнее: [интеграция](iacpaas-integration.md).
- Без ключа модели нельзя считать live-подключение OpenRouter проверенным.
- После аварийного завершения процесса незавершённый запрос может остаться `pending`. Автоматический повтор неизвестного исхода запрещён; до сверки оператором этот диалог возвращает 409, остальные диалоги доступны.


## Вход IACPaaS и управление диалогами

В настройках доступны логин и пароль IACPaaS. Если профиль ещё не сохранён, используются значения окружения сервера. Пустой пароль сохраняет прежнее значение, а отдельный флажок удаляет его. При смене логина требуется новый пароль. Профиль хранится в SQLite с ограниченными правами файла, как API-профили; шифрование БД приложением не выполняется. Пароль не возвращается браузеру и не включается в промпт. Дочерний MCP получает снимок окружения только своего пользователя. Для удалённого MCP вход настраивается на стороне того сервера.

В меню «⋯» рядом с диалогом доступны «В архив» и «Удалить». Архив хранит переписку полностью; из списка «Архив» диалог восстанавливается. Архивный диалог доступен для чтения, отправка требует восстановления. Удаление с подтверждением удаляет сообщения, события, запросы и рабочую сводку выбранного диалога. Отдельные версии диалога сохраняют свои копии. Во время незавершённого запроса архивирование и удаление блокируются.

HTTP API (same-origin, cookie и CSRF для POST):

- `GET/POST /api/platform/settings` — публичный профиль без пароля / сохранение `username`, `password`, `clear_password`.
- `POST /api/platform/settings/test` — вход и чтение одного разрешённого ресурса без LLM.
- `POST /api/conversations/{id}/manage` с `action: archive|restore|delete`.
- `GET /api/conversations` возвращает также `archived`; UI разделяет активный список и архив.

Примеры вопросов выбираются локально: два из десяти, без генерации и оплаты. Старый `/api/suggestions` удалён.
