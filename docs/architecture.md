# Архитектура

```text
                         MCP stdio / Streamable HTTP
VS Code + custom agent ─────────────────────────────┐
                                                   ▼
Python CLI → agent loop → MCP client ──────→ MCP server → GraphService → Backend
                 │                             │                       │
          model adapter                  policy gate           MockBackend
          demo / OpenAI-compatible             │
                                            audit

Веб-чат → HTTP API → ConversationAgent → MCP client → тот же MCP server
              │             │
              └─ SQLite     └─ OpenRouter / OpenAI / Codex
```

## Компоненты

- **Backend и GraphService:** каталог ресурсов, чтение и изменение нормализованных графов, обход, поиск, подсчёт и проверка структуры.
- **MCP-сервер:** публичные инструменты и схемы, обработка ошибок, ограничения, stdio/HTTP и политика записи.
- **Клиенты:** отдельный Python-агент и VS Code. Оба используют один MCP-контракт.
- **Веб-приложение:** `gas_web` обслуживает статический чат, проверяет владельца сессии/CSRF и сохраняет полную историю в SQLite. `standalone_agent.conversation` выполняет собственный read-only цикл, формирование связного ответа, сверку ссылок/чисел и сжатие рабочего контекста. Резюме хранится отдельно от исходных сообщений.

Адаптер и доменные функции работают внутри процесса сервера. Для них не требуется отдельный сетевой сервис. LLM подключается со стороны клиента и не вызывается MCP-сервером.

## Транспорты

**stdio:** клиент запускает дочерний процесс и обменивается MCP-сообщениями через stdin/stdout. Логи направляются в stderr.

**Streamable HTTP:** сервер запускается отдельно и принимает запросы на `/mcp`. Для локального доступа используется bearer-токен. Полноценная OAuth-инфраструктура в текущей конфигурации не реализована.

Транспорт не меняет набор инструментов или семантику операций.

## Модель данных

Текущий MockBackend хранит синтетические данные в формате `normalized-demo-v1`. Он не является форматом universal, meta или simple IACPaaS. Каждый экземпляр backend имеет собственное состояние в памяти; перезапуск восстанавливает фикстуру.

Реальный `IACPaaSBackend` читает universal-экспорт, а `normalize_universal` преобразует его в `normalized-iacpaas-v1` с путями, типами значений, ссылками, клонами и происхождением. Внешние оригиналы не загружаются автоматически; ошибка подключения не включает mock. Подробнее: [интеграция](iacpaas-integration.md).

## Собственный разговорный цикл веб-чата

1. `gas_web.app` проверяет владельца/CSRF и записывает вопрос через `Storage.start_turn`.
2. `ConversationAgent` получает доступные read-only MCP-инструменты и собирает рабочий контекст.
3. Если бюджет превышен, модель сжимает старую завершённую часть беседы; полные сообщения остаются в SQLite. Намерение вопроса и необходимость инструментов определяются моделью по промпту, без шаблонных ответов по совпадению фразы.
4. Модель либо сразу отвечает/уточняет, либо возвращает пояснение и вызовы MCP. Число вызовов, размер результатов и время выполнения ограничены.
5. MCP проверяет аргументы и политику, GraphService обращается к адаптеру платформы. Результаты возвращаются модели как данные.
6. Пояснения и события чтения передаются в браузер по SSE до итогового ответа.
7. Модель формирует обычный Markdown со ссылками на свидетельства текущего хода. JSON-обёртка не обязательна; прежние структурированные форматы принимаются для совместимости.
8. `answers.py` сверяет ссылки и числа. `verification.py` проверяет явные числовые нормативные привязки и отдельным запросом модели сверяет смысл каждого блока с источниками и вопросом. Неподтверждённый вывод не публикуется. Отчёт сохраняется в `verification.review`.
9. `Storage.finish_turn` сохраняет итог, источники, ход работы, сводку и ответ на запрос для повторного использования без повторного запуска модели.

Сжатие запускается по оценке контекста с запасом для ответа и результатов инструментов. По умолчанию лимит — 48000 условных токенов, резерв ответа — 4096, инструментального обмена — 8192 байта, резюме — 2048 байт. Оценка основана на UTF-8-размере и служебном запасе, а не точном tokenizer. Сводка хранит границу покрытия сообщений и заменяет только модельное представление старой части.

## Примеры вопросов

Пустой чат показывает два случайных вопроса из десяти заранее подготовленных. «Другие примеры» выбирает новую пару без обращения к модели; нажатие на карточку только заполняет поле ввода. Ответы готовит общий агентный цикл, готовых предметных ответов нет.

## CLI и независимое подключение MCP

CLI с `--model openai` и веб-чат используют одно ядро `ConversationAgent`: общий промпт, контекст, MCP-политика и проверка ответа. CLI передаёт результаты в терминал/JSONL, веб — в SSE/SQLite. `runtime.py` сохраняет отдельный сценарный стенд `demo` и совместимость прежних тестов; это не второй рабочий цикл LLM. Транспорт CLI находится в `models.py`; для внешних оболочек MCP остаётся самостоятельным.

В Docker работают веб-сервис и агент, а MCP при stdio-подключении запускается дочерним процессом на время хода. Внешний клиент может независимо запускать тот же пакет MCP через stdio либо подключаться к отдельно запущенному HTTP-серверу. Серверу не нужны веб-чат или ключ языковой модели; для реальных ресурсов нужны собственные настройки IACPaaS.

## Доступ и изменения

Сервер запрещает запись по умолчанию. Оператор разрешает её через конфигурацию процесса и ограничивает область `/demo/`. Аргументы инструментов не могут включить эту политику. CLI отдельно запрашивает согласие пользователя.

Серверный policy gate не является сервисом одноразовых подтверждений: клиент с доступом к разрешённому серверу может выполнять операции в пределах его политики. Сервер не следует публиковать в общедоступной сети с такой конфигурацией.

Отдельные stdio-процессы имеют независимые данные. HTTP-клиенты одного процесса разделяют backend. Для будущей записи через API IACPaaS необходимы проверка прав, read-back и обработка неизвестного исхода без автоматического повтора.

Профили входа IACPaaS обслуживает `gas_web/platform_settings.py`. Архив — флаг диалога; удаление транзакционно очищает его сообщения, события, запросы и ссылки на версии, сохраняя другие ветки.
