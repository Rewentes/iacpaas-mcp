# Архитектура

```text
                         MCP stdio / Streamable HTTP
VS Code + custom agent ─────────────────────────────┐
                                                   ▼
Python CLI → agent loop → MCP client ──────→ MCP server → GraphService → Backend
                 │                             │                       │
             model adapter                  policy gate           MockBackend
          demo / OpenAI-compatible             │
                                            audit
```

## Компоненты

- **Backend и GraphService:** каталог ресурсов, чтение и изменение нормализованных графов, обход, поиск, подсчёт и проверка структуры.
- **MCP-сервер:** публичные инструменты и схемы, обработка ошибок, ограничения, stdio/HTTP и политика записи.
- **Клиенты:** отдельный Python-агент и VS Code. Оба используют один MCP-контракт.

Адаптер и доменные функции работают внутри процесса сервера. Для них не требуется отдельный сетевой сервис. LLM подключается со стороны клиента и не вызывается MCP-сервером.

## Транспорты

**stdio:** клиент запускает дочерний процесс и обменивается MCP-сообщениями через stdin/stdout. Логи направляются в stderr.

**Streamable HTTP:** сервер запускается отдельно и принимает запросы на `/mcp`. Для локального доступа используется bearer-токен. Полноценная OAuth-инфраструктура в текущей конфигурации не реализована.

Транспорт не меняет набор инструментов или семантику операций.

## Модель данных

Текущий MockBackend хранит синтетические данные в формате `normalized-demo-v1`. Он не является форматом universal, meta или simple IACPaaS. Каждый экземпляр backend имеет собственное состояние в памяти; перезапуск восстанавливает фикстуру.

Реальный адаптер должен преобразовывать проверенный экспорт IACPaaS во внутреннюю модель, учитывать пути, внешние ссылки, типы значений и неполные результаты. Ошибка реального подключения не должна приводить к скрытому переходу на mock.

## Агентный цикл

Запрос пользователя → discovery MCP-инструментов → решение модели → проверка бюджета и подтверждения → MCP-вызов → результат или ошибка → следующий вызов, уточнение либо итоговый ответ.

`demo` — детерминированный сценарный парсер. `openai` — адаптер Chat Completions с tool calling. Результаты инструментов передаются модели как данные, а не как инструкции. Журнал JSONL содержит вызовы, аргументы, результаты, статусы и длительность.

## Доступ и изменения

Сервер запрещает запись по умолчанию. Оператор разрешает её через конфигурацию процесса и ограничивает область `/demo/`. Аргументы инструментов не могут включить эту политику. CLI отдельно запрашивает согласие пользователя.

Серверный policy gate не является сервисом одноразовых подтверждений: клиент с доступом к разрешённому серверу может выполнять операции в пределах его политики. Сервер не следует публиковать в общедоступной сети с такой конфигурацией.

Отдельные stdio-процессы имеют независимые данные. HTTP-клиенты одного процесса разделяют backend. Для будущей записи через API IACPaaS необходимы проверка прав, read-back и обработка неизвестного исхода без автоматического повтора.
