# Архитектура

## Границы системы

```text
                         MCP stdio / Streamable HTTP
VS Code + custom agent ─────────────────────────────┐
                                                   ▼
Python CLI → agent loop → MCP client ──────→ MCP server → GraphService → Backend
                 │                             │                       │
             model adapter                  policy gate           MockBackend
          demo / OpenAI-compatible             │                  (сейчас)
                                            audit                HTTP IACPaaS
                                                               (позднее)
```

IACPaaS — внешняя платформа, не часть этого репозитория. MCP — протокол. MCP-сервер — отдельный исполняемый процесс. Адаптер и доменные функции — модули внутри этого процесса, а не дополнительные микросервисы.

## Три зоны ответственности

1. **Платформа и графы:** интерфейс backend, тестовые данные, получение ресурса, обход, поиск, подсчёт и изменение нормализованного графа.
2. **MCP-сервер (роль Евгения):** публичные инструменты, типизированные схемы, два транспорта, перевод ошибок, ограничения и серверная политика записи.
3. **Клиенты:** отдельный Python-агент, подключение модели, последовательные вызовы, уточнения, трасса и конфигурация VS Code.

Тесты и документация каждого слоя принадлежат его владельцу; сквозная проверка общая. Деление описывает компоненты, а не подтверждённый вклад реальных людей. При подготовке использовались три параллельных программных агента и общая интеграция.

## Два транспорта, один сервер

- **stdio:** клиент запускает сервер как дочерний процесс, передаёт MCP по stdin/stdout. Диагностика идёт в stderr. Сетевой порт не нужен.
- **Streamable HTTP:** отдельный сервер слушает localhost; клиент подключается к `/mcp`. Используется локальный bearer-токен, не полноценная OAuth-инфраструктура. Это учебный стенд, не интернет-публикация.

Публичные инструменты и доменная логика одни и те же. Выбор транспорта не меняет смысл операции.

## Данные и реальный API

Демонстрационные данные синтетические и помечены `mock`. `normalized-demo-v1` — внутренний учебный формат; это **не** universal, meta или simple IACPaaS. Работающий обход внутреннего графа не доказывает правильность парсинга настоящего экспорта.

Реальную интеграцию подключаем отдельно: получаем разрешённый экспорт, фиксируем форму ответа и ссылки, преобразуем в внутреннюю модель и добавляем регрессионные фикстуры. Нельзя молча подменять сбой реального backend тестовыми данными.

## Агентный цикл

Пользовательский запрос → список доступных MCP-инструментов и их схем → решение модели → проверка бюджета и подтверждения записи → MCP-вызов → результат или диагностируемая ошибка → следующий шаг либо ответ/уточнение.

Режим `demo` — ограниченная детерминированная сценарная модель для воспроизводимости, **не LLM**. Реальная модель подключается отдельно через OpenAI-совместимый API; модель не имеет прямого доступа к доменным функциям или ключу IACPaaS. Самостоятельный runtime допустим заданием как сопоставимая агентная среда; LangChain/LangGraph в этой реализации не заявляются.

## Запись и доверие

Запись по умолчанию запрещена сервером. Разрешение выдаёт оператор через конфигурацию процесса, с ограничением пути. Значение `confirmed=true`, сгенерированное моделью, не является разрешением. CLI дополнительно спрашивает человека, а неинтерактивный режим отклоняет изменение.

Это **явный policy gate**, разрешённый исходным заданием; не реализация отдельного одноразового сервиса одобрения из расширенного плана. Если оператор разрешил серверу запись, другой MCP-клиент с доступом к этому серверу также может её вызвать в пределах политики — поэтому разрешение нельзя выдавать на общедоступном стенде.

Изменения MockBackend существуют в памяти процесса. Перезапуск восстанавливает фикстуру. Отдельные stdio-процессы имеют независимое состояние; HTTP-клиенты одного процесса используют общий backend. Для реальной IACPaaS позже нужны проверка прав платформы, сверка результата и обработка неизвестного исхода без слепого повторения записи.
