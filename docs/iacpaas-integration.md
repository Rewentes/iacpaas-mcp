# Подключение реальных ресурсов IACPaaS

Адаптер IACPaaS читает настроенные инфоресурсы для MCP-сервера и веб-агента. Он преобразует universal JSON в граф и сохраняет происхождение данных.

## Настройка и запуск

В локальном `.env` задайте `IACPAAS_BACKEND=iacpaas` и пути ресурсов по шаблону `.env.example`. Пути указываются относительно «Моего фонда». Для самостоятельного MCP-сервера задайте `IACPAAS_USERNAME` и `IACPAAS_PASSWORD` в окружении. В веб-чате можно сохранить данные входа в настройках браузерного профиля.

```sh
uv run --frozen --env-file .env iacpaas-mcp
uv run --frozen --env-file .env iacpaas-web --host 127.0.0.1 --port 8080 --db ./private-data/chat.sqlite3
```

Это независимые способы запуска: первый нужен внешней MCP-оболочке; второй запускает веб-приложение, чей агент поднимает MCP через stdio. Одновременно выполнять обе команды для веб-чата не требуется. Сетевой транспорт MCP использует тот же адаптер и отдельный `MCP_HTTP_TOKEN`.

## Авторизация и чтение

`POST /api/signin` получает логин и пароль, возвращает JWT в `accessToken`. Токен остаётся в памяти MCP-процесса и передаётся только официальному HTTPS-адресу IACPaaS. При отклонённом JWT читающий запрос может быть повторён один раз после нового входа. Отказ доступа и неуспешный вход возвращаются явно.

`GET /api/data/export/user-item` вызывается с `path`, `json-type=universal`, `no-blob-data=true`, без ограничения глубины. Фактический ответ содержит `filename`, `code`, `data`; JSON ресурса находится строкой в `data`. Адаптер также распознаёт оболочку `result`. До JSON-разбора ограничивается размер распакованного тела ответа.

## Операции MCP

| Инструмент | Реальная операция |
|---|---|
| `list_inforesources` | Настроенный каталог; не листинг всего фонда |
| `get_inforesource` | Метаданные и количества из проверенного полного экспорта |
| `query_graph` | Поиск по полям вершин экспорта |
| `get_subgraph` | Ограниченный обход полученного графа |
| `count_graph` | Подсчёт уникальных идентификаторов и экземпляров дуг в указанной области |
| `export_inforesource` | Нормализованный граф `normalized-iacpaas-v1`, не исходный universal |
| `validate_resource` | Проверка структуры нормализованного графа; не проверка всех требований онтологии |
| `get_gas_specification` | Извлечение поддерживаемых нормативных границ состава вершины «Газ» |
| `update_concept`, `import_inforesource` | Явный отказ для реального источника |

Временный кэш действует внутри одного MCP-процесса до 60 секунд, настройка `IACPAAS_CACHE_SECONDS=0..300`. Ответ сохраняет исходное `source.fetched_at` и дату изменения платформы. Просроченный кэш не используется при ошибке свежего запроса. Постоянного поискового индекса и скрытого перехода к старым данным нет.

## Граф и ссылки

Вершины сохраняют идентификаторы платформы строками, тип, метапонятие, типизированное значение и комментарий. Рёбра сохраняют метапонятие отношения, `specifier`, `restrictor`, `rcomment`. Повторная ссылка на уже описанную вершину добавляет дугу без дублирования самой вершины. Для клона сохраняются собственный идентификатор и отдельная ссылка на оригинал.

Внешние оригиналы не загружаются автоматически. Поле `reference` сохраняет вид ссылки, идентификатор цели и путь без идентификатора аккаунта. Связанный настроенный ресурс можно явно прочитать теми же инструментами. Поэтому количество вершин описывает конкретный экспорт, а не всю транзитивно связанную базу знаний.

## Нормативный состав газа

Последовательность: найти ресурс через `list_inforesources`, найти точную вершину газа через `query_graph` с небольшим `limit`, затем вызвать `get_gas_specification(path, concept_id)`.

Поддерживаются явно заданные ветви «Объемные доли компонентов» с числовыми значениями, знаками ≤/≥ и единицами. Число, единица и оператор должны присутствовать в данных; недостающие значения не восстанавливаются по догадке. Для совокупности веществ сохраняется суммарное ограничение. Неподдерживаемая структура приводит к `complete=false` и предупреждению.

Для условной марки газа основной компонент может иметь нижнюю нормативную границу, а примесь — верхнюю. Границы описывают требования к составу. Состав многокомпонентных смесей и числовые интервалы доступны в исходном графе через общие инструменты.

Агент регистрирует нормативные факты с идентификатором числовой вершины, названием газа и компонента, единицей и оператором. Модель использует их ID в связном ответе и в `source_ids`; ссылки сверяются с реестром текущего запроса, числа — с выбранными фактами. Сверка чисел дополняется проверкой нормативных привязок и отдельной модельной проверкой всех смысловых блоков, включая связь с газом и соответствие вопросу. При успехе ответ получает `reviewed`, при противоречии или незавершённой проверке неподтверждённый вывод не публикуется. Автоматический отчёт не является абсолютной гарантией правильности. Старый вывод полей без пересказа и строгий `claims` остаются для совместимости. Подробнее: [разговорный цикл и границы проверки](web.md). При недостатке места ограничивается набор предложенных модели доказательств, исходный результат инструмента не обрезается. Полная переписка и источники сохраняются в SQLite.

## Проверки и пределы

- Экспорт: по умолчанию 16 MiB, конфигурация от 1 KiB до 64 MiB.
- Граф: до 50000 уникальных вершин, 200000 вхождений, глубина universal до 128.
- Публичный подграф MCP: глубина 0..5, до 2000 вершин; поиск — до 100 результатов.
- Не выполняются реальные записи, импорт, удаление или автоматическое раскрытие всех внешних ссылок.

Источники контрактов: [удалённые вызовы IACPaaS](https://iacpaas.dvo.ru/docs/RemoteCalls/RemoteCalls.html), [OpenAPI](https://iacpaas.dvo.ru/v3/api-docs), [universal JSON](https://iacpaas.dvo.ru/docs/Json/Json.html).
