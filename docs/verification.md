# Автоматические проверки

## Команды

Из корня проекта:

```sh
uv sync --frozen
uv run --frozen ruff check .
PYTHON_DOTENV_DISABLED=1 uv run --frozen pytest -q
```

В PowerShell перед тестами задайте `$env:PYTHON_DOTENV_DISABLED = "1"`, затем выполните `uv run --frozen pytest -q`. Это не даёт тестовому веб-CLI автоматически подхватить личную `.env`.

Пересборка интерфейса:

```sh
cd frontend
npm ci
npm run build
```

Вернитесь в корень перед Python-командами. Сборка обновляет поставляемую статику и хэши её загрузки.

## Что проверяют тесты

| Область | Покрытие | Где искать |
|---|---|---|
| Mock-графы | Обход, повторные дуги, внешние цели, строгая структура `normalized-demo-v1` и запреты записи | `tests/test_domain.py`, `test_backend.py`, `test_regressions.py` |
| MCP | Настоящий SDK: in-memory streams, stdio-подпроцесс и TCP HTTP, схемы, ошибки, авторизация и бюджеты | `tests/test_server.py`, `test_http.py`, `test_integration.py` |
| CLI | Демо, работа общего цикла с модельным адаптером, подтверждения и трассы | `tests/test_agent.py`, `test_agent_cli.py` |
| Разговор и контекст | Исправление ответа по замечаниям, цитаты, история, сжатие, лимиты | `tests/extended/`, `test_working_summary.py`, `test_tool_working_memory.py` |
| Настройки | Изоляция профилей, ключей и путей, миграции, ошибки провайдеров | `tests/extended/`, `test_resource_settings.py`, `test_native_default.py` |
| Контроллеры интерфейса | Меню, переименование, редакторы настроек | `tests/test_conversation_menu.py`, `test_rename_form.py`, `test_platform_form.py` |
| Документация | Существование ссылок, синтетические JSON-примеры и соответствие снимков схем серверу | `tests/test_documentation.py` |

Контрактные проверки используют реальные транспорты MCP, но синтетические графы и подставленные ответы платформы/модели. Это проверяет обработку заданного контракта, а не доступность настоящего аккаунта или неизменность внешнего API.

Сценарии согласования проверяют передачу автору числовых и смысловых замечаний, повторную сверку исправлений, дополнительные чтения в прежнем бюджете, ошибочный вердикт проверяющего, полезный частичный ответ и продолжение обсуждения после сжатия. Они не гарантируют качество любой внешней модели.

## Действующий CI

Единственная конфигурация — [.github/workflows/test.yml](../.github/workflows/test.yml):

- Ubuntu и Windows, Python 3.12/3.13: закреплённый `uv`, установка, Ruff и pytest.
- Отдельное Docker-задание: сборка, запуск веба, ожидание `/healthz`, запрос `/api/me`, остановка стенда.

В CI нет настоящих ключей IACPaaS и провайдеров. Docker smoke не отправляет сообщение модели и не читает реальный ресурс. `/healthz` подтверждает работоспособность сервиса и БД, а не интеграцию с внешними системами.

## Что проверяется отдельно

Визуальное поведение в целевых браузерах, реальное подключение IDE, права и пути IACPaaS, изменения API, модели провайдеров, предметная корректность нормативов и удалённый доступ требуют [приёмки на реальном окружении](acceptance.md).

Эта страница описывает методику и покрытие. Приватные результаты живых/платных проверок, учётные данные, переписка и экспорты в репозиторий не входят. Актуальные границы компонентов перечислены в [status.md](status.md).
