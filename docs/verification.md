# Проверка автономной версии

## Что реально выполнено

Проверки выполнялись на Linux в среде Hermes. Обе установки используют `uv.lock`, без изменения исходников под отдельный запуск.

| `ruff check .` | All checks passed |
| `pytest -q`, Python 3.14.7 | 48 passed |
| Чистое не-editable окружение, Python 3.13.5 | 48 passed |
| Wheel сборка и запуск вне каталога проекта | CLI находит packaged demo.json и возвращает 5 вершин / 6 дуг |
| Реальная stdio MCP-сессия | initialize, tools/list, связанные tools/call успешны |
| Реальный HTTP-процесс на localhost | initialize, tools/list и вызовы успешны |
| HTTP без токена | 401 |
| Совпадение count_graph stdio / HTTP | одинаковые структурированные результаты |
| Прямой MCP-вызов записи при выключенной политике | permission_denied, без изменения |

Проверка TTY использовала псевдотерминал и ввод тестового harness. Она проверяет ветку программы, но не является протоколом решения настоящего пользователя.

## Интеграционный RED → GREEN

1. Сквозной тест stdio был добавлен до готовности сервера и падал с `Connection closed`. После сборки частей и установки пакета он проходит.
2. Отдельный тест обнаружил, что `IACPAAS_BACKEND=iacpaas` игнорировался: процесс запускал mock и возвращал код 0. Значение env включено в выбор backend; тест проходит с диагностикой unsupported_backend.
3. Независимое ревью воспроизвело частичную утечку синтетического секрета на границе обрезки строки и ошибку размера ответа уже применённой записи. Добавлены 4 регрессионных случая: секрет маскируется до обрезки; большая запись возвращает ограниченное успешное подтверждение; оба вида записи при слишком малом бюджете отклоняются до изменения. Проверены read-back и статус аудита.
4. Журналы вертикальных срезов каждого компонента: development-platform.md, development-server.md, development-agent.md. Они описывают наблюдавшиеся прогоны, не историю трёх реальных одногруппников.

## Независимая проверка кода

Первое ревью воспроизвело два дефекта (redaction на границе обрезки и ответ размера после мутации). После исправлений повторное независимое ревью не нашло оставшихся замечаний по этим двум проблемам; регрессионные и связанные тесты прошли. Финальный полный набор отдельно выполнен интегратором: 48 passed на каждой из двух проверенных версий Python. Это локальная проверка, не GitHub Actions.

## Что не проверялось и не объявляется готовым

- Настоящая IACPaaS, её аккаунты, права, ошибки REST и форматы universal/meta/simple.
- Платный или иной реальный LLM-провайдер. Проверен контракт OpenAI-совместимого адаптера через тестовый HTTP transport.
- Выполнение трёх сценариев непосредственно в VS Code, доверие серверу и password prompts.
- Windows/macOS; исполнение проверено только на Linux, в частности trace использует POSIX-защиту файла.
- Python 3.11/3.12: допустимость синтаксиса и зависимости не равны выполненному тестовому прогону.
- Удалённый production HTTP/OAuth. Текущая защита предназначена для локального учебного стенда.
- GitHub Actions: шаблон находится в ci/, но workflow не активирован из-за отсутствия scope workflow у текущей авторизации. Локальный зелёный suite не называется удалённым CI.

## Известные ограничения

- Mock не сохраняет изменения после завершения процесса.
- Сценарный demo parser не заменяет LLM и не понимает произвольные параметры естественного языка.
- Шаблон custom agent задаёт инструкции, но сам по себе не гарантирует жёсткий бюджет/подтверждение в IDE.
- Redaction трассы — best effort, не DLP. Не передавайте секреты в данные и проверяйте trace до публикации.
- Если полный ответ уже применённой записи слишком велик, сервер возвращает ограниченное успешное подтверждение applied=true/result_omitted=true, complete=false, а не ложную ошибку записи. Если даже это подтверждение не помещается, операция отклоняется до изменения. Автоматические повторы записей запрещены; неизвестный сетевой исход в будущем реальном backend требует read-back.

Таким образом проверен работающий автономный стенд. Итоговая приёмка учебного задания на реальной платформе остаётся отдельным этапом.
