# Проверка проекта

Исходные тесты находятся в `tests/`; они используют синтетические ресурсы и подставленные ответы модели. Команды:

```sh
uv sync --frozen
PYTHON_DOTENV_DISABLED=1 uv run --frozen pytest -q
uv run --frozen ruff check .
cd frontend && npm ci && npm run build
```

Проверяются MCP stdio/HTTP, схемы и ограничения, графовые операции, политика записи, клиент CLI, обработка ошибок и происхождение фактов. Переносимые регрессии в `tests/extended/` охватывают разговорный цикл, сжатие контекста, цитаты с диапазонами, передачу полных документов проверке, профили провайдеров, секреты IACPaaS, архив/восстановление/удаление и сохранность веток переписки.

Браузерные проверки на синтетических данных покрывают промежуточные события, Markdown, ссылки, редактирование/перегенерацию, темы, прокрутку, мобильную ширину и действия с диалогами. Они не требуют платного обращения к модели.

Для живой проверки отдельно нужны собственные данные входа IACPaaS, разрешённые пути ресурсов и ключ выбранного провайдера. Переносимость реальных прав пользователя и доступность внешней модели локальные тесты не доказывают. Автоматическая модельная сверка может дать ошибочную оценку; отчёт и первоисточники доступны пользователю. Факт проверки не означает независимую экспертизу нормативов.

`ci/github-actions.yml.example` — переносимый шаблон CI; его можно установить как `.github/workflows/test.yml`. Секреты, личная переписка, трассы и экспорты ресурсов не входят в репозиторий.
