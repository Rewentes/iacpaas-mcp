# Общая подготовка к защите

## Как честно представить работу

Проект разделён на три зоны ответственности. При подготовке кода использовались три параллельных программных агента и последующая общая интеграция. Документы в `roles/` — материалы для изучения и выступления, не история участия конкретных одногруппников. Укажите имена и реальные доработки после совместной проверки. Если учебные правила требуют раскрывать использование ИИ, сообщите об этом.

## Вводная часть

«Мы делаем единый MCP-сервер для доступа к графовым ресурсам IACPaaS и два способа работы с ним: VS Code и отдельное Python-приложение. Сейчас интеграция с настоящей платформой отложена, поэтому демонстрируем автономный стенд на явно обозначенных синтетических данных. Сервер, протокол, обход графа и клиентские вызовы при этом выполняются настоящим кодом».

## Порядок выступления

1. Участник 1 объясняет тестовый граф, backend и подсчёт.
2. Евгений объясняет MCP-контракт, два транспорта и серверную защиту записи.
3. Участник 3 показывает агента, последовательность вызовов, уточнение и трассу; затем конфигурацию VS Code.
4. Вместе показываете протокол проверок и перечисляете оставшиеся шаги: настоящая IACPaaS, реальный LLM-провайдер и ручной прогон IDE.

## Общие вопросы

**Где здесь ИИ?** В LLM-режиме модель выбирает инструменты по их схемам и данным предыдущих шагов. Режим demo нужен для автономной проверки, он не выдаётся за модель.

**Зачем mock, если задание про IACPaaS?** Чтобы независимо разрабатывать и проверять сервер и клиентов до получения доступа. Для окончательной платформенной приёмки mock недостаточно.

**Можно ли считать работу полностью сданной?** Нет, пока не проверены фактическая IACPaaS и сценарии в IDE. В репозитории отмечены реализованные части и ещё не выполненные проверки.

**Нужен ли отдельный репозиторий для каждого сервиса?** Нет. Репозиторий общий, процессы разные. Backend — модуль, а не дополнительный микросервис.

**Где хранить ключи?** В локальном окружении или секретном хранилище. `.env.example` содержит только имена настроек; заполненный `.env` исключён из git. В VS Code секреты вводятся отдельно.

**Почему схема не гарантирует безопасную запись?** Типы проверяют форму аргументов, но право на изменение и намерение человека — отдельные проверки.

- Проверить все выбранные команды из demo.md.

- Для VS Code заранее проверить доступ к выбранной модели и доверие MCP-серверу.
