# Участник 3: Python-агент и VS Code

Материал для подготовки участника 3. Выполните сценарии клиента и проверьте настройки VS Code перед выступлением; рассказывайте о наблюдаемых результатах.

## За что отвечает участник

- `src/standalone_agent/`: MCP-клиент, модель, агентный цикл, CLI и трасса.
- `.vscode/`: способы подключения сервера.
- `.github/agents/iacpaas.agent.md`: роль и ограничения агента IDE.
- Сценарии и тесты клиентской логики.

## Текст выступления

«Моя часть — приложение, которое связывает запрос человека, модель и MCP-сервер. В отличие от сервера, агент выбирает последовательность действий. Он получает схемы инструментов, передаёт их модели и выполняет предложенные вызовы через MCP.

Например, пользователь просит найти ресурс и показать сведения о нём. Сначала агент вызывает list_inforesources. Затем берёт путь из ответа и передаёт его в get_inforesource. Это связанные вызовы: второй шаг использует данные первого. Нельзя подставить выдуманный идентификатор только потому, что он выглядит правдоподобно.

Если параметров не хватает, приложение запрашивает уточнение. Если инструмент сообщает ошибку, её получает следующий шаг модели, чтобы скорректировать действие. Число вызовов ограничено: иначе неудачный план может бесконечно повторяться и расходовать запросы.

Для воспроизводимой демонстрации есть режим demo. Это ограниченная сценарная модель, а не настоящая LLM. Она выполняет реальные MCP-вызовы, но выбирает шаги по известным сценариям. Отдельно предусмотрено подключение OpenAI-совместимой модели. Без API-ключа мы не заявляем, что проверили реального провайдера.

Каждый вызов записывается в JSONL: инструмент, аргументы, результат, статус и длительность. Секреты должны маскироваться. Перед изменением CLI спрашивает человека; в неинтерактивном запуске изменение отклоняется. При этом окончательное разрешение всё равно проверяет сервер.

Второй клиент — VS Code. Для него подготовлены конфигурация MCP и файл custom agent с ограничениями и сценариями. Он подключается к тому же серверу, а не к отдельной копии API. Выполнение трёх сценариев непосредственно в IDE нужно проверить на машине команды: подготовка конфигурационных файлов ещё не означает успешный прогон интерфейса».

## Что показать

1. Подключение MCP-клиента и tools/list.
2. Два последовательных вызова и передачу пути из первого во второй.
3. Уточнение недостающего пути.
4. Ошибку, затем ограниченное восстановление.
5. JSONL-трассу без секретов.
6. VS Code-конфигурацию и ограничения .agent.md.

## Вопросы на защите

**Чем demo отличается от LLM?** В demo выбор шагов детерминирован и ограничен сценариями. В LLM-режиме решения возвращает внешняя модель. Протокол MCP и сервер при этом одинаковые.

**Почему свой runtime?** Задание допускает сопоставимую агентную среду. Здесь цикл небольшой и проверяемый; LangChain/LangGraph не обязательны и не заявляются использованными.

**Можно ли просто вызвать GraphService из CLI?** Тогда мы обошли бы MCP и не проверили работу отдельного клиента. В этой реализации агент работает через MCP.

**Что мешает модели самой подтвердить запись?** Решение принимает ввод человека в CLI, а сервер проверяет отдельную конфигурационную политику. Текст модели не заменяет ни один из этих шагов.
