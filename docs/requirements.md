# Соответствие учебному заданию

Основание: предоставленный документ «02_Описание_учебной_задачи_IACPaaS_MCP_Agent.docx». Документ «03» — расширенный инженерный план, а не отдельное обязательное ТЗ. Материалы «01» — справочники, не готовый совместимый стек.

| Требование | Где реализуется / как проверяется |
|---|---|
| MCP-сервер-адаптер к IACPaaS | MCP работает с MockBackend; **настоящая IACPaaS отложена по решению пользователя** |
| Локальный stdio и транспорт для HTTP-подключения | Общая фабрика сервера, CLI выбора транспорта; протокольные тесты |
| Единая доменная логика | GraphService используется обоими транспортами |
| Типизированные входы и выходы, JSON Schema | Аннотации, Pydantic, MCP tools/list и outputSchema |
| Отсутствие внутренних секретных полей в схемах | Ключи не являются аргументами tools; настройки сервера отдельно |
| Разделение чтения и изменения | Отдельные tools и аннотации, не заменяющие политику |
| Подтверждение или policy gate | Запрет записи по умолчанию, доверенная конфигурация и allowlist; дополнительный запрос CLI |
| Структурированные данные и ошибки | Успешный envelope; MCP isError с диагностикой |
| Последовательные вызовы и уточнения | Agent loop, получение схем, сценарные тесты |
| VS Code workspace-конфигурация и .agent.md | Файлы подготовлены; **ручной прогон внутри VS Code не выполнен на сервере без GUI** |
| Три сценария непосредственно в VS Code | Сценарии описаны; выполнение командой по инструкции ещё требуется |
| Python standalone с тем же сервером | MCP-клиент stdio/HTTP, CLI, одинаковые tools |
| LangChain/LangGraph или сопоставимый runtime | Собственный небольшой tool-calling цикл, без заявления об использовании LangChain |
| Сохранение tool calls | JSONL-трасса, фильтрация секретов, лимиты |
| Исходники и инструкции | Репозиторий, README, docs |

## Что не объявляется выполненным

- Подключение и проверка настоящей IACPaaS, её прав и форматов universal/meta/simple.
- Прогон выбранного реального LLM-провайдера без предоставленных пользователем доступа/модели.
- Проверка трёх сценариев в фактически установленном VS Code на машине команды.
- Полноценный удалённый production OAuth-сервер и одноразовый сервис согласования записи.

Система представляет работающий автономный учебный стенд и каркас для последующей интеграции, а не окончательное подтверждение всех критериев реальной платформы.

## О наборе инструментов

Названия в разделе 4 исходного задания — пример. Реализация должна покрывать сценарии и объяснять соответствие операций, но не обязана придумывать несуществующие одноимённые методы платформы. Итоговый обязательный объём подтверждает преподаватель.
