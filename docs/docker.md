# Запуск приложения в Docker

Веб-чат, собственный агент и MCP-процесс работают в одном контейнере. MCP запускается агентом через stdio, отдельный сетевой порт ему не нужен. Самостоятельный запуск MCP вне Docker сохраняется.

Команды выполняются из корня репозитория. После запуска приложение доступно по адресу [http://127.0.0.1:8080](http://127.0.0.1:8080). По умолчанию порт доступен только локально.

## Запуск и управление

```sh
# Сборка и запуск
docker compose --env-file /dev/null up -d --build

# Состояние и журналы
docker compose --env-file /dev/null ps
docker compose --env-file /dev/null logs --tail 100 -f

# Остановка
docker compose --env-file /dev/null stop

# Повторный запуск
docker compose --env-file /dev/null up -d

# Обновление после изменений исходников
docker compose --env-file /dev/null up -d --build

# Применение изменений приватного .env
docker compose --env-file /dev/null up -d --force-recreate
```

`--env-file /dev/null` относится к самой Compose: она не интерполирует пароль и ключи из приватного `.env`. Файл `.env` монтируется только при запуске как read-only secret в `/run/secrets/app_env`. Веб-CLI читает его через собственный `--env-file` с отключённой подстановкой переменных. Значения ключей не включаются в Dockerfile, образ, команду запуска или Compose environment.

Образ работает с UID/GID 1000. Согласуйте права локального файла `.env` с пользователем контейнера и ограничьте доступ к этому файлу.

## Данные

Постоянный том `iacpaas_app_data` монтируется в `/data`:

- `/data/chat.sqlite3` — владельцы браузерных сессий, переписка, источники, запросы и профили моделей;
- `/data/codex-accounts` — отдельные каталоги Codex каждого владельца;
- `/data/home` — домашний каталог контейнерного пользователя.

Обычная остановка и пересоздание контейнера сохраняют том. Проверено сохранение владельца, CSRF, полной истории, профиля модели и повторной выдачи сохранённого ответа без нового вызова агента. Для этого использовались отдельная техническая сессия и синтетические сообщения; платные запросы не выполнялись.

## Резервная копия

Для согласованной копии SQLite и файлов авторизации приложение на время останавливается. Выберите новое имя архива:

```sh
umask 077
mkdir -p private-data/backups
docker compose --env-file /dev/null stop web
docker compose --env-file /dev/null run --rm --no-deps --entrypoint tar web \
  -C /data -czf - . > private-data/backups/iacpaas-data.tar.gz
docker compose --env-file /dev/null up -d
```

Архив включает приватные профили и возможную авторизацию Codex; храните его как приватный файл. `.env` хранится отдельно и также нужен для восстановления. `private-data/` исключён из Git и контекста сборки.

## Доступ по локальной сети

Текущий запуск привязан к `127.0.0.1`. Для согласованного LAN-адреса укажите его в `IACPAAS_TRUSTED_HOSTS` приватного `.env`, затем пересоздайте контейнер с конкретным адресом публикации, например:

```sh
IACPAAS_BIND_ADDRESS=192.0.2.25 docker compose --env-file /dev/null up -d --force-recreate
```

Здесь `192.0.2.25` — адрес из диапазона для документации, замените его действительным адресом своего компьютера. Переменная `IACPAAS_WEB_PORT` при необходимости меняет порт хоста. `0.0.0.0` внутри контейнера не разрешает произвольные Host: проверяются точные имена/IP, wildcard отвергается. Для недоверенной сети нужны HTTPS и отдельная аутентификация приложения.

## Состав и ограничения

Базовые образы Python и uv закреплены digest. Python-зависимости устанавливаются по `uv.lock`, без dev-группы. В финальном образе нет исходной `.env`, БД хоста, тестов, pytest, Ruff, npm или Node. Включён нативный официальный Codex `0.167.0` с его штатными файлами; авторизация компьютера не переносится.

Контейнер работает непривилегированным пользователем, с read-only корневой файловой системой, временным `/tmp`, сброшенными capabilities и запретом повышения привилегий. Домашние каталоги хоста и Docker socket не монтируются. `/healthz` проверяет доступность БД, не создавая новую браузерную идентичность и не вызывая модель или платформу.

Профиль Codex использует изолированный каталог авторизации для каждого владельца браузерной сессии. Вход и проверка модели запускаются в настройках веб-чата.

Подробности проверки проекта описаны в [verification.md](verification.md).
